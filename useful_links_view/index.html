01 / Une lecture utile à ton besoin actuel

Commence par une seule piste.

  • Une notion Kotlin reste floue ? Reprends une notion dans le tour Kotlin et essaie son exemple.
  • Tu veux comprendre un écran ? Pars des bases Compose, puis cherche le composant utilisé dans ton quiz.
  • Tu veux améliorer ton outil d’images ? Lis un exemple du tutoriel Pillow avant de modifier ton script.

Une documentation technique contient souvent plus d’options que tu n’en utilises aujourd’hui. Lis le passage qui répond à ta question, puis vérifie ton interprétation avec un petit exemple ou ton encadrant.

Les langues sont indiquées pour t’aider à choisir. Si tu utilises une traduction ou l’agent pour comprendre une page en anglais, garde les noms d’API, de fichiers et de commandes tels qu’ils sont écrits.

05 / Lire un projet à travers une question

Quatre dépôts GitHub à explorer.

Ces projets répondent à des besoins et des niveaux différents. Choisis un exemple ou une fonction ; tu peux commencer par lire dans GitHub sans tout cloner ou lancer.

Kotlin · Pour pratiquer une notion

Kotlin / kotlin-koans-edu

Le contenu des exercices Kotlin Koans : une occasion de reconnaître les petites fonctions, les classes et les collections dans des exercices ciblés.

Première lecture : le README, puis le dossier Introduction. Pour pratiquer, le README conseille notamment la version en ligne ; cloner ce dépôt n’est pas nécessaire.

Question à explorer : quelles valeurs une fonction reçoit-elle, et quel résultat doit-elle produire ?

Android / Compose · Lecture ciblée avec l’encadrant

Android / compose-samples

Des applications d’exemple officielles pour voir Compose dans des interfaces plus complètes que notre quiz.

Première lecture : le README, puis un seul exemple, comme JetNews. Repère un écran et ses composants avant d’examiner le reste.

Question à explorer : où l’écran reçoit-il ses données et ses actions ? Ces exemples peuvent utiliser ViewModel et d’autres choix ; compare les responsabilités à notre presenter sans imposer toute leur architecture au quiz.

Compose Multiplatform · Après la fenêtre Desktop

JetBrains / compose-multiplatform

Le projet Compose Multiplatform et son dossier d’exemples, dont certains visent plusieurs plateformes.

Première lecture : la liste des exemples, puis Imageviewer si tu veux suivre le thème des images. Choisis la cible qui t’intéresse dans son README.

Question à explorer : quelles parties décrivent l’interface commune et lesquelles préparent la plateforme ? Le dépôt est vaste ; ce point d’entrée suffit pour une première visite.

Python / Pillow · Curiosité avancée

python-pillow / Pillow

Le code de la bibliothèque que ton script utilise. Il permet de voir comment un outil de ton projet est développé et documenté.

Première lecture : le README, puis le fichier src/PIL/Image.py pour rechercher thumbnail. Commence par sa description et sa signature plutôt que par tout son fonctionnement interne.

Question à explorer : quelle différence entre appeler une méthode de bibliothèque et écrire cette méthode ? Pour utiliser Pillow, conserve la bibliothèque installée par uv ; ce dépôt n’a pas à être copié dans le quiz.

06 / Revenir avec une explication vérifiable

Utilise l’agent pour guider une lecture.

Avant de lancer ou reprendre du code, lis le README, les prérequis et le fichier de licence du dépôt. Les exemples peuvent demander d’autres versions d’outils que ton quiz. Prépare leur exécution avec l’encadrant dans un dossier distinct.

Si tu veux utiliser un projet comme référence, précise ce que l’agent doit examiner et quels fichiers il peut lire. Par exemple :

Je veux comprendre une idée de ce dépôt : [URL ou chemin local].
Ma question est : [un besoin précis, par exemple comment l’écran reçoit ses actions].
Commence sans modifier de fichier et indique ce que tu as effectivement consulté.
Trouve un exemple limité et explique-le avec les notions de mon quiz.
Donne les fichiers et les noms de fonctions qui étayent ton explication.
Si tu ne peux pas accéder au contenu, signale-le.
Propose ensuite ce qui serait utile à mon projet, avec les adaptations nécessaires.

Ouvre un des fichiers cités et retrouve le passage décrit. Pour réutiliser du code, conserve la référence d’origine et examine les conditions de sa licence avec l’encadrant. Une simple lecture ou une demande d’explication ne demande pas de créer une PR.

Une bonne visite peut se terminer avec trois éléments : une question de départ, un exemple retrouvé et une idée que tu peux expliquer avec tes mots.
