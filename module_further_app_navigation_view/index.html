01 / Deux espaces dans une même application

Accueil conserve ton quiz ; Profil commence vide.

Tu as déjà un parcours fonctionnel et des fiches de révision. Nous allons maintenant organiser l’app en deux destinations principales : « Accueil », avec tout ce qui fonctionne déjà, et « Profil », une surface blanche pour commencer.

La barre du bas montre une maison et une silhouette de profil, avec leurs libellés. Le pager et la barre doivent rester synchronisés : un clic change la page, un balayage change la destination sélectionnée.

Une seule position de navigation.

La page courante du pager indique aussi quel élément de la barre est sélectionné. N’ajoute pas un deuxième numéro d’onglet à mettre à jour manuellement.

Pas encore de prise de photo, d’autorisation ou de formulaire de profil sur cette page. Le nouvel espace doit seulement apparaître et laisser revenir au quiz.

02 / Regrouper les fichiers qui travaillent ensemble

Un package terminé par _view pour chaque MVP.

Nous choisissons une convention d’équipe : chaque groupe de fichiers d’un MVP d’écran est rangé dans un package terminé par _view. Ce suffixe aide à reconnaître ces groupes quand l’application grandit ; ce n’est pas une règle imposée par Kotlin.

fr/stageacademy/quiz/
├── MainActivity.kt
├── Question.kt
├── home_view/
│   ├── HomeView.kt
│   ├── QuizContract.kt
│   └── QuizPresenter.kt
└── profile_view/
    ├── ProfileView.kt
    ├── ProfileContract.kt
    └── ProfilePresenter.kt

home_view regroupe la vue, le contrat et le presenter existants du quiz. Le suffixe qualifie le groupe ; il ne transforme pas son presenter en composant visuel. Les données Question restent ici hors des packages de vue.

  1. Avec l’encadrant, garde une trace Git de la version fonctionnelle avant de déplacer les fichiers.
  2. Crée home_view sous fr.stageacademy.quiz. Déplace l’ancien accueil et son parcours dans HomeView.kt, avec ses helpers privés comme QuestionView et ReviewScreen.
  3. Renomme la fonction d’entrée de ce parcours en HomeView, avec le paramètre modifier: Modifier = Modifier. Garde son code et son état existants.
  4. Déplace QuizContract et QuizPresenter dans ce même package. Fais corriger les déclarations package et les imports par la fonction de déplacement de l’IDE.
  5. Compile avant d’ajouter la seconde page : un déplacement seul ne doit pas changer le résultat du quiz.

HomeView doit être accessible depuis MainActivity : ne la déclare pas privée au fichier. Les helpers internes peuvent le rester s’ils sont utilisés dans le même fichier. Ajoute notamment les imports de Question et de R lorsque les fichiers déplacés les utilisent. Mets aussi les prévisualisations à jour.

Mon agent a créé une organisation un peu différente

Fais repérer les fichiers actuels puis déplacer l’ensemble cohérent, sans reconstruire le quiz. Mets à jour AGENTS.md avec la convention des packages _view, en conservant les consignes déjà utiles.

AppContent complète — le bloc d’assemblage fourni
@Composable
private fun AppContent() {
    val pagerState = rememberPagerState(pageCount = { 2 })
    val coroutineScope = rememberCoroutineScope()
    val profilePresenter: ProfileContract = remember { ProfilePresenter() }

    Scaffold(
        modifier = Modifier.fillMaxSize(),
        bottomBar = {
            NavigationBar {
                NavigationBarItem(
                    selected = pagerState.currentPage == 0,
                    enabled = !pagerState.isScrollInProgress,
                    onClick = {
                        coroutineScope.launch { pagerState.animateScrollToPage(0) }
                    },
                    icon = {
                        Icon(painterResource(R.drawable.ic_home), contentDescription = null)
                    },
                    label = { Text("Accueil") },
                )
                NavigationBarItem(
                    selected = pagerState.currentPage == 1,
                    enabled = !pagerState.isScrollInProgress,
                    onClick = {
                        coroutineScope.launch { pagerState.animateScrollToPage(1) }
                    },
                    icon = {
                        Icon(painterResource(R.drawable.ic_profile), contentDescription = null)
                    },
                    label = { Text("Profil") },
                )
            }
        },
    ) { innerPadding ->
        HorizontalPager(
            state = pagerState,
            beyondViewportPageCount = 1,
            modifier = Modifier.fillMaxSize().padding(innerPadding),
        ) { page: Int ->
            if (page == 0) {
                HomeView(modifier = Modifier.fillMaxSize())
            } else {
                ProfileView(
                    presenter = profilePresenter,
                    modifier = Modifier.fillMaxSize(),
                )
            }
        }
    }
}

Dans le setContent existant de MainActivity, garde ton thème et appelle cette fonction à la place de l’ancien bloc principal :

QuizTheme {
    AppContent()
}

innerPadding réserve l’espace de la barre et des zones système : le contenu ne doit pas être masqué en dessous. Les icônes sont accompagnées de libellés ; leur description est nulle pour ne pas répéter ces mêmes mots.

Le premier indice est 0 (« Accueil »), le second 1 (« Profil »). La barre lit currentPage, et ses clics demandent un déplacement au même pager. Les boutons sont désactivés pendant ce déplacement.

05 / Passer d’un espace à l’autre sans perdre la partie

Conserver en mémoire n’est pas sauvegarder.

Le pager peut retirer des pages qui ne sont plus nécessaires. Si le presenter et l’état du quiz appartiennent à une vue retirée, les recréer peut réinitialiser la partie.

Pour cette première application à seulement deux destinations, beyondViewportPageCount = 1 garde aussi la page voisine composée. Les deux vues et leurs états restent ainsi présents pendant le changement d’onglet.

Un choix limité à cette étape.

Garder les deux pages est simple ici. Cela ne sauvegarde pas les données sur disque et ne garantit pas la conservation après recréation de l’activité ou arrêt du processus. On ne généralise pas ce réglage à une grande collection.

Si l’app grandit, on pourra donner explicitement un propriétaire plus durable à l’état de chaque espace. La page sur le cycle de vie des données explique pourquoi le nom d’un package ne décide pas de la durée de vie des objets.

Autre conséquence : ProfileView peut déjà être composée alors que l’onglet Accueil est visible. La prochaine page devra déclencher la caméra ou sa demande d’autorisation au bon moment, pas simplement parce qu’une fonction de vue est appelée.

Le pager de révision existe aussi dans Accueil

Ce sont deux navigations différentes. Vérifie qui reçoit le geste quand le pager de révision arrive à une extrémité. Si un balayage peut changer d’espace, assure-toi que la barre l’indique clairement et que la fiche est conservée au retour. Les boutons de révision et de navigation restent des moyens explicites de choisir le déplacement.

💡

Page composée

Une vue dont les composants sont présents dans la composition, même si elle n’est pas la page actuellement visible.

💡

Propriétaire de l’état

La partie du programme qui conserve une information et décide de sa durée de vie.

06 / Vérifier avant la caméra

Deux destinations, un quiz toujours fonctionnel.

  1. Lance l’app : « Accueil » est sélectionné et le parcours existant est accessible.
  2. Clique sur « Profil » : une page blanche apparaît, l’icône Profil est sélectionnée et aucune caméra ou autorisation ne s’ouvre.
  3. Reviens par la barre puis passe d’une destination à l’autre par balayage. La sélection doit suivre le pager.
  4. Commence une partie, réponds à une question et note le score, le message et les boutons disponibles. Passe à Profil puis reviens : ces informations doivent être conservées.
  5. Refais l’expérience après une mauvaise réponse : les choix doivent rester désactivés. Cela vérifie plus que le seul score.
  6. Termine une partie, ouvre la révision, change d’espace puis reviens. Vérifie la destination et l’état de lecture attendus ; observe aussi les gestes aux extrémités du pager de révision.
  7. Vérifie le résultat et le recommencement : le déplacement des fichiers ne doit pas avoir changé les règles.
