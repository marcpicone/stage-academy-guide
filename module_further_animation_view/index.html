01 / Un changement plus facile à percevoir

Pourquoi animer le retour après une réponse ?

Le joueur clique sur un choix. Le programme vérifie la réponse et le message change. Une apparition progressive peut aider à remarquer ce retour sans ajouter une nouvelle règle de jeu.

On va garder l’invitation « Choisis une réponse. » avant le clic, puis faire apparaître le message correct ou incorrect. Le texte restera lisible une fois l’animation terminée.

L’état dit quoi afficher ; l’animation accompagne son apparition.

Le presenter vérifie et compte les points comme avant. La vue anime seulement la présentation du message. On ne retarde ni le calcul ni l’activation de « Question suivante ».

Illustration interactive en HTML/CSS pour le cours : elle ne lance pas Compose, ne valide pas de réponse et ne calcule pas le score.

Le résultat devient visible progressivement.

Décoche puis recoche pour revoir l’apparition. Si les animations sont réduites dans ton système, ce schéma affiche directement le texte.

02 / Réutiliser une information existante

Un Boolean pilote la visibilité.

Dans la version du cours, QuestionView utilise déjà canGoToNextQuestion. Cette valeur est fausse avant une réponse et vraie après. Elle permet donc aussi de décider quand montrer le résultat.

  1. Avant la réponse : false.

    L’invitation à choisir est affichée. Le résultat est masqué.

  2. Après le clic : true.

    La validation, le message et le score sont mis à jour par le code existant. Le résultat apparaît avec une transition.

  3. À la question suivante.

    La vue de cette question retrouve son état initial. Une nouvelle réponse pourra déclencher une nouvelle apparition.

AnimatedVisibility affiche ou masque un contenu selon un Boolean. Pour cet exercice, fadeIn choisit une apparition en fondu ; la durée précise le temps de la transition. Ces composants sont décrits dans la documentation Android.

Il ne suffit pas de remplacer le texte alors que la visibilité reste vraie pour relancer cette animation. Ici, on anime le passage de masqué à visible, pas chaque changement de phrase.

💡

Visibilité · visibility

Le fait qu’un élément soit montré ou masqué. Ici, elle dépend de l’état de réponse.

💡

Fondu · fade

Une apparition ou disparition progressive par changement d’opacité.

💡

Durée · duration

Le temps prévu pour une transition. Dans l’exemple, on l’exprime en millisecondes : 1 000 ms correspondent à une seconde.

03 / Une petite modification dans la vue

Anime le message, garde la validation.

Ouvre ton clone Android avec l’encadrant. Le code ci-dessous s’appuie sur QuestionView de la page sur les contrats. Si un agent a réorganisé le design, retrouve le bloc équivalent et conserve les styles déjà choisis.

  1. Repère le message qui affiche feedbackText et les états utilisés par les boutons.
  2. Ajoute les imports suivants en haut du fichier, sans dupliquer ceux qui existent déjà.
  3. Remplace uniquement le Text(text = feedbackText) de la vue par le bloc fourni. Garde la fonction de validation et les boutons.
import androidx.compose.animation.AnimatedVisibility
import androidx.compose.animation.fadeIn
import androidx.compose.animation.fadeOut
import androidx.compose.animation.core.tween
if (!canGoToNextQuestion) {
    Text(text = "Choisis une réponse.")
}
AnimatedVisibility(
    visible = canGoToNextQuestion,
    enter = fadeIn(animationSpec = tween(durationMillis = 300)),
    exit = fadeOut(animationSpec = tween(durationMillis = 300)),
) {
    Text(text = feedbackText)
}

! signifie « pas » : l’invitation s’affiche tant qu’on ne peut pas passer à la suite. visible reçoit ensuite le Boolean qui déclenche l’apparition du résultat.

enter décrit l’entrée et exit la sortie. tween permet ici de fixer leur durée. Tu peux d’abord utiliser ces lignes fournies sans apprendre toutes les options de courbe ou de mouvement.

Dans notre parcours, on observe surtout l’entrée. Si la vue de la question est retirée ou réinitialisée lors du passage à la suivante, ne suppose pas qu’une sortie animée sera jouée : cette transition nécessite que le composant reste présent pendant le changement de visibilité.

Ma fonction n’utilise plus ces noms depuis les exercices avec l’agent

Demande-lui de repérer la valeur qui distingue avant et après réponse, puis d’animer seulement le résultat. Fournis le code actuel et la référence de cette étape. Ne recrée pas un second calcul de score ou une seconde validation dans la vue.

L’apparition ne recommence pas à la question suivante

Vérifie l’état local de la question. Dans la version du cours, les valeurs sont mémorisées avec le presenter et l’indice de question comme clés. Si elles ne reviennent pas à leur état initial, le contenu peut rester visible. Corrige ce lien avec l’encadrant plutôt que d’ajouter un délai arbitraire.

Le composant Compose qui anime l’affichage ou le masquage de son contenu.

« Entrée » / « sortie » : les transitions choisies pour apparaître ou disparaître.

04 / Comparer avant et après

La présentation change, les règles restent identiques.

  1. Lance le quiz : l’invitation est visible et le résultat masqué avant une réponse.
  2. Réponds correctement : observe le fondu de « Bonne réponse ! », le point ajouté une seule fois et les choix désactivés.
  3. Passe à la question suivante et réponds incorrectement : le message incorrect apparaît, le score ne gagne pas de point.
  4. Termine puis recommence : vérifie la première question, le score à zéro et la nouvelle apparition après une réponse.
  5. Compare temporairement une durée de 300 ms à 900 ms. Annonce ce qui doit changer avant de relancer.

Une durée plus longue doit changer le temps du fondu, pas le moment de la validation ou le nombre de points. « Question suivante » ne doit pas attendre la fin de l’effet. Tu peux donc quitter une question avant la fin du fondu : l’animation n’est pas la règle du jeu.

Choisis ensuite une durée courte qui rend le résultat perceptible sans gêner. Le message doit rester compréhensible même si l’animation n’est pas jouée.

Pourquoi ne pas mettre une attente avant d’ajouter le point ?

Ce serait changer le comportement du quiz. Ici, l’état est mis à jour après la réponse et la vue accompagne son affichage. Le calcul n’a pas besoin d’attendre l’effet visuel.

💡

Transition

Le passage visuel entre deux situations. Elle accompagne le changement d’état sans remplacer les règles du programme.

05 / À toi de choisir un effet utile

Explique le besoin avant de choisir l’animation.

Présente la modification à l’encadrant en répondant à ces questions : quel changement voulais-tu rendre visible ? Quel état le déclenche ? Que se passerait-il si on retirait l’animation ?
