Donner un déroulement au quiz

Faire avancer le quiz.

Au lieu d’afficher toutes les questions, montre-les une par une. Le joueur répond, lit le résultat, puis demande à passer à la suivante.

Le presenter va retenir où en est le quiz. La vue lira ses informations après chaque action pour mettre l’écran à jour. Nous n’ajoutons pas encore de score.

01 / Définir le comportement

Répondre, puis avancer.

  1. Au lancement, la première question est affichée et « Question suivante » est désactivé.
  2. Le joueur choisit une réponse. Le message indique le résultat et « Question suivante » devient disponible.
  3. Un clic sur « Question suivante » affiche la question suivante, avec son message initial et le bouton à nouveau désactivé.
  4. Après une réponse à la dernière question et un dernier clic sur « Question suivante », l’écran affiche « Quiz terminé ».

Une réponse incorrecte suffit à débloquer la suite : on exige d’avoir répondu, pas d’avoir trouvé la bonne réponse. Le joueur peut changer son choix tant qu’il reste sur la même question. Aucun point n’est compté dans cet exercice.

Avec l’encadrant, garde la version précédente dans Git puis prépare une branche, par exemple ab/faire_avancer_le_quiz.

02 / Retenir où nous en sommes

Un indice et une information vrai/faux.

Le presenter reçoit les questions lors de sa création. Il doit conserver deux informations :

private var currentQuestionIndex: Int = 0
private var hasAnsweredCurrentQuestion: Boolean = false

currentQuestionIndex est l’indice de la question courante : 0 pour la première. hasAnsweredCurrentQuestion indique si le joueur a déjà donné une réponse pour cette question.

Ces propriétés sont dans la classe, en dehors de ses méthodes : les actions de la même instance peuvent les lire et les modifier. Elles ne disparaissent pas à la fin d’un appel comme une variable locale.

private les réserve à l’intérieur de la classe. La vue ne doit pas écrire directement un nouvel indice : elle demande l’action goToNextQuestion() pour respecter la règle.

État du quiz · presenter
Question courante, réponse donnée et fin du parcours.
État d’affichage · vue
Message, activation du bouton et informations relues pour afficher l’étape actuelle.

03 / Les actions modifient l’état

Fais évoluer QuizPresenter.

Remplace le contenu de QuizPresenter.kt par ce cadre. Lis d’abord submitAnswer et goToNextQuestion : l’une marque qu’une réponse a été donnée, l’autre avance puis remet cette information à false.

package fr.stageacademy.quiz

class QuizPresenter(private val questions: List<Question>) {
    private var currentQuestionIndex: Int = 0
    private var hasAnsweredCurrentQuestion: Boolean = false

    fun getCurrentQuestionIndex(): Int {
        return currentQuestionIndex
    }

    fun isFinished(): Boolean {
        return currentQuestionIndex >= questions.size
    }

    fun getCurrentQuestion(): Question {
        return questions[currentQuestionIndex]
    }

    fun isCorrectAnswer(
        question: Question,
        selectedAnswer: String,
    ): Boolean {
        val result: Boolean = selectedAnswer == question.correctAnswer
        return result
    }

    fun submitAnswer(selectedAnswer: String): Boolean {
        if (isFinished()) {
            return false
        }
        val question: Question = getCurrentQuestion()
        val isAnswerCorrect: Boolean = isCorrectAnswer(question, selectedAnswer)
        hasAnsweredCurrentQuestion = true
        return isAnswerCorrect
    }

    fun canGoToNextQuestion(): Boolean {
        return hasAnsweredCurrentQuestion
    }

    fun goToNextQuestion(): Unit {
        if (canGoToNextQuestion()) {
            currentQuestionIndex = currentQuestionIndex + 1
            hasAnsweredCurrentQuestion = false
        }
    }
}

La règle isCorrectAnswer est conservée. L’action submitAnswer l’utilise pour la question courante, conserve le fait d’avoir répondu et renvoie le résultat à afficher.

La méthode goToNextQuestion ne fait rien si aucune réponse n’a été donnée. Sinon, elle ajoute 1 à l’indice et remet hasAnsweredCurrentQuestion à false. Un deuxième appel immédiat ne saute donc pas une autre question.

Vérifie la fin avant de lire la question.

Pour quatre questions, les indices valides sont 0, 1, 2 et 3. Après la dernière, l’indice vaut 4 et isFinished renvoie true. À ce moment, on affiche la fin au lieu d’appeler getCurrentQuestion.

>= signifie « supérieur ou égal ». Dans isFinished, nous vérifions si l’indice a atteint le nombre de questions. getCurrentQuestion doit être appelé uniquement quand le quiz n’est pas terminé ; il lit directement la liste.

Et si la liste des questions était vide ?

Dès le départ, 0 est égal à la taille 0. isFinished vaut donc true. L’écran de fin s’affiche sans demander de question. La vue doit conserver cette vérification avant l’accès à la liste.

💡

Constructor · constructeur

QuizPresenter(questions) reçoit maintenant la liste au moment de créer l’instance. Elle devient une propriété privée en lecture dans cette classe.

💡

« Envoyer la réponse » / « passer à la question suivante ». Les noms annoncent des actions qui modifient l’état du quiz.

💡

canGoToNextQuestion / isFinished

« Peut-on passer à la suivante ? » / « le quiz est-il terminé ? ». Ces méthodes fournissent des informations sans avancer.

04 / Rendre le changement visible

Une action, puis une relecture explicite.

Le presenter est une classe Kotlin ordinaire. Modifier son indice ne suffit pas à prévenir Compose. La vue garde des valeurs observées pour l’affichage, puis les actualise après l’action :

presenter.goToNextQuestion()
displayedQuestionIndex = presenter.getCurrentQuestionIndex()
isQuizFinished = presenter.isFinished()

L’indice et le statut affichés sont relus depuis le presenter : la vue ne décide pas elle-même d’ajouter 1 ni d’autoriser un saut. Ces deux lignes sont nécessaires pour que Compose décrive l’écran avec la nouvelle situation.

Le bouton de réponse fait de même : il appelle submitAnswer, choisit le message, puis relit canGoToNextQuestion. Le bouton « Suivante » reçoit ce Boolean dans son paramètre enabled.

QuestionView complète : réponses et bouton Suivante
@Composable
fun QuestionView(
    question: Question,
    questionIndex: Int,
    presenter: QuizPresenter,
    onNextQuestion: () -> Unit,
) {
    var feedbackText: String by remember(presenter, questionIndex) {
        mutableStateOf("Choisis une réponse.")
    }
    var canGoToNextQuestion: Boolean by remember(presenter, questionIndex) {
        mutableStateOf(presenter.canGoToNextQuestion())
    }

    fun checkAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = presenter.submitAnswer(selectedAnswer)
        if (isAnswerCorrect) {
            feedbackText = "Bonne réponse !"
        } else {
            feedbackText = "Essaie encore."
        }
        canGoToNextQuestion = presenter.canGoToNextQuestion()
    }

    Column(
        verticalArrangement = Arrangement.spacedBy(12.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(text = question.text)
        for (choice: String in question.choices) {
            Button(onClick = { checkAnswer(choice) }) {
                Text(text = choice)
            }
        }
        Text(text = feedbackText)
        Button(
            onClick = onNextQuestion,
            enabled = canGoToNextQuestion,
        ) {
            Text(text = "Question suivante")
        }
    }
}

onNextQuestion: () -> Unit est un paramètre qui reçoit une action sans paramètre et sans résultat utile à récupérer. Comme le onClick de Button, il permet de transmettre du travail à faire plus tard. Ici, WelcomeScreen fournit l’action et QuestionView la confie au bouton.

Le cadre remember utilise maintenant le presenter et l’indice de la question. Quand on passe à l’indice suivant, le message et l’activation du bouton repartent de leur état initial, même si deux questions ont le même texte.

💡

Callback · action de rappel

Une action transmise à un autre élément pour être exécutée plus tard. Ici, onNextQuestion est déclenchée au clic sur « Suivante ».

💡

enabled · activé

Le Boolean qui indique si le bouton peut être utilisé. Le presenter conserve aussi la règle pour empêcher un saut si l’action est appelée sans réponse.

💡

displayedQuestionIndex

« Indice de la question affichée » : une valeur observée par Compose, relue après l’action.

05 / Une question ou l’écran de fin

Assemble WelcomeScreen.

Garde Question.kt sans changement. Dans MainActivity.kt, remplace WelcomeScreen et QuestionView par les versions de cette page ; garde MainActivity, sa prévisualisation et les imports existants.

Le presenter doit être créé après la liste des questions, puisqu’il la reçoit. Le cadre ci-dessous reprend les quatre questions connues :

WelcomeScreen complet
@Composable
fun WelcomeScreen(modifier: Modifier = Modifier) {
    val firstQuestion: Question = Question(
        text = "Quel outil garde l’historique du code ?",
        choices = listOf("Git", "Android", "Compose"),
        correctAnswer = "Git",
    )

    val secondQuestion: Question = Question(
        text = "Quel composant Compose affiche du texte ?",
        choices = listOf("Button", "Text", "Column"),
        correctAnswer = "Text",
    )

    val thirdQuestion: Question = Question(
        text = "Quel mot-clé déclare une fonction en Kotlin ?",
        choices = listOf("fun", "val", "if"),
        correctAnswer = "fun",
    )

    val fourthQuestion: Question = Question(
        text = "Quel type représente vrai ou faux ?",
        choices = listOf("String", "Boolean", "Int"),
        correctAnswer = "Boolean",
    )

    val questions: List<Question> = listOf(
        firstQuestion,
        secondQuestion,
        thirdQuestion,
        fourthQuestion,
    )
    val presenter: QuizPresenter = remember(questions) { QuizPresenter(questions) }
    var displayedQuestionIndex: Int by remember(presenter) {
        mutableStateOf(presenter.getCurrentQuestionIndex())
    }
    var isQuizFinished: Boolean by remember(presenter) {
        mutableStateOf(presenter.isFinished())
    }

    Column(
        modifier = modifier
            .fillMaxSize()
            .verticalScroll(rememberScrollState())
            .padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(24.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(
            text = stringResource(R.string.welcome_title),
            style = MaterialTheme.typography.headlineMedium,
        )
        if (isQuizFinished) {
            Text(text = "Quiz terminé")
        } else {
            Text(text = "Question ${displayedQuestionIndex + 1}")
            val question: Question = presenter.getCurrentQuestion()
            QuestionView(
                question = question,
                questionIndex = displayedQuestionIndex,
                presenter = presenter,
                onNextQuestion = {
                    presenter.goToNextQuestion()
                    displayedQuestionIndex = presenter.getCurrentQuestionIndex()
                    isQuizFinished = presenter.isFinished()
                },
            )
        }
    }
}

Il n’y a plus de boucle affichant toutes les questions. Le if choisit entre « Quiz terminé » et une seule QuestionView. getCurrentQuestion est appelé uniquement dans la branche où le quiz n’est pas terminé.

Le texte "Question ${displayedQuestionIndex + 1}" insère un numéro dans le message. On ajoute 1 pour présenter « Question 1 » au joueur quand l’indice vaut 0.

remember(questions) conserve ici le presenter tant que les questions restent identiques. Les valeurs d’affichage sont liées à cette instance avec remember(presenter). Rien n’est sauvegardé durablement : un redémarrage de l’activité peut recommencer le quiz.

Garde le trajet lisible.

Clic → action sur le presenter → lecture du nouvel état → mise à jour des valeurs observées → nouvel affichage. La vue ne doit pas avancer un indice dans un coin pendant que le presenter en garde un autre.

💡

Une instance conservée

Créer un nouveau presenter à chaque clic le remettrait au début. Nous conservons l’instance pour qu’elle retienne l’avancement.

💡

Écran de fin

Un affichage choisi quand toutes les questions ont été parcourues. Ce n’est pas un élément supplémentaire dans la liste.

06 / Tester les transitions

Vérifie le début, chaque passage et la fin.

  1. Lance le quiz : seule la première question doit apparaître. « Suivante » est désactivé.
  2. Choisis une réponse incorrecte. Lis le résultat et vérifie que « Suivante » est maintenant activé.
  3. Change pour la bonne réponse, puis clique sur « Suivante ». La question 2 apparaît avec le message « Choisis une réponse. » et le bouton désactivé.
  4. Continue pour les questions 3 et 4. Après chaque passage, aucun ancien message ne doit rester.
  5. Après une réponse à la dernière question, clique sur « Suivante » : seul le titre et « Quiz terminé » restent affichés. Aucun accès à un indice invalide ne doit faire fermer l’app.
L’écran reste sur la même question

Vérifie que la réponse passe par submitAnswer. Au clic suivant, vérifie l’appel goToNextQuestion puis les deux relectures vers displayedQuestionIndex et isQuizFinished. Modifier uniquement une propriété du presenter ne déclenche pas automatiquement une mise à jour Compose.

L’app se ferme après la dernière question

Lis Logcat avec l’encadrant. Vérifie notamment que getCurrentQuestion est dans la branche qui ne s’exécute que si le quiz n’est pas terminé. Après le dernier passage, l’indice atteint la taille de la liste et n’est plus utilisable pour en lire un élément.
