Choisir ce que les autres peuvent utiliser

private et public : qui peut utiliser quoi ?

La vue peut demander une validation et lire le score. Elle ne doit pas modifier directement le score ou l’indice. La visibilité permet d’écrire cette limite dans le code.

Tu as déjà rencontré private dans le presenter. Nous allons comprendre son rôle, le comparer à public et rendre privés deux détails qui n’ont pas besoin d’être appelés ailleurs.

01 / Garder les règles cohérentes

Demander une action plutôt que modifier un détail.

Dans ton quiz, submitAnswer compte au plus une fois la première réponse. goToNextQuestion exige une réponse avant d’avancer. Ces règles dépendent du score, de l’indice et des informations privées conservées par le presenter.

Si la vue pouvait écrire directement presenter.score = 100 ou changer l’indice, elle pourrait contourner ces règles. Nous voulons qu’elle utilise les actions prévues et qu’elle puisse lire les résultats nécessaires.

À utiliser depuis la vue
submitAnswer, getScore, goToNextQuestion, restart…
À garder à l’intérieur
score, currentQuestionIndex, les informations de réponse et les détails de calcul.

Une partie du programme a besoin de connaître les services d’une autre partie, pas tous ses détails internes.

💡

Visibilité · visibility

La règle qui détermine d’où le code peut accéder à une déclaration : une classe, une propriété ou une fonction.

💡

Détail interne

Une information ou une action nécessaire au fonctionnement d’une partie du code, mais qui n’a pas à être utilisée directement ailleurs.

02 / À l’intérieur d’une classe

private réserve l’accès à cette classe.

Dans QuizPresenter, le score est déclaré ainsi :

private var score: Int = 0

fun getScore(): Int {
    return score
}

Les méthodes de QuizPresenter peuvent lire et modifier score. En revanche, le code de la vue ne peut pas lire directement presenter.score ni lui donner une valeur, même si la vue se trouvait dans le même fichier que la classe.

La vue peut appeler presenter.getScore(). Elle reçoit le nombre à afficher ; elle n’obtient pas le droit de modifier la propriété privée.

Exemple volontairement incorrect : que refuse le compilateur ?
// Depuis le code de la vue :
presenter.score = 100

L’accès à score est refusé parce que cette propriété est privée à QuizPresenter. Il ne faut pas retirer private pour faire disparaître le message : il faut retrouver l’action autorisée qui correspond au besoin.

La visibilité aide à faire respecter la responsabilité.

Le presenter contrôle les points en fonction des réponses. La vue lui transmet les actions et affiche les résultats.

💡

private · privé

Pour un membre de classe, l’accès direct est réservé au code de cette classe.

💡

Encapsulation

Garder les détails internes ensemble et contrôler la façon dont les autres parties les utilisent. Le score privé et les actions du presenter en donnent un premier exemple.

03 / Les opérations proposées aux autres

public rend l’élément utilisable depuis l’extérieur.

Dans notre projet, les méthodes du presenter utilisées par la vue sont publiques. En Kotlin, public est la visibilité par défaut pour ces déclarations :

fun getScore(): Int {
    return score
}

écrit la même visibilité que :

public fun getScore(): Int {
    return score
}

Tu n’es donc pas obligé d’écrire public partout. Nous l’écrivons sur getScore dans l’exemple complet pour rendre ce choix visible.

Public ne signifie pas « tout le monde peut tout modifier ». Une propriété déclarée avec val reste non réaffectable, même si elle est publique. La visibilité détermine qui peut accéder ; val ou var détermine si la valeur peut être remplacée.

Le type Question doit rester accessible depuis MainActivity.kt et QuizPresenter.kt. Le presenter doit aussi rester accessible au code qui le crée. On ne rend pas une déclaration privée simplement parce qu’elle est dans un fichier séparé.

À toi : faut-il rendre getScore privée pour protéger le score ?

Non. La propriété score reste privée, mais la vue doit pouvoir lire le total via getScore. Rendre cette méthode privée empêcherait l’appel nécessaire à l’affichage.

💡

public · public

L’élément peut être utilisé par le code extérieur qui a accès au type ou à la déclaration. Ici, la vue peut appeler les méthodes publiques du presenter.

💡

Public dans le code / sur GitHub

Le mot-clé public de Kotlin ne change pas les réglages de partage du dépôt GitHub. Il décrit les accès dans le programme.

04 / Le sens dépend de l’emplacement

private au niveau du fichier.

Quand une fonction est déclarée en dehors des classes et des autres fonctions, private la réserve au fichier où elle est écrite.

Voici un exemple de lecture, indépendant du quiz :

private fun formatScore(score: Int, questionCount: Int): String {
    return "Score : $score / $questionCount"
}

fun getExampleLabel(): String {
    return formatScore(3, 4)
}

getExampleLabel peut appeler formatScore parce que les deux sont dans ce fichier. Une fonction dans un autre fichier ne peut pas appeler directement formatScore, même avec le même package. Un import ne contourne pas cette limite.

Dans ton application, QuestionView est déclarée au niveau de MainActivity.kt et n’est appelée que depuis ce fichier. On peut donc écrire :

@Composable
private fun QuestionView(
    question: Question,
    questionIndex: Int,
    presenter: QuizPresenter,
    onAnswerSubmitted: () -> Unit,
    onNextQuestion: () -> Unit,
) {
    // Le corps existant est conservé.
}

WelcomeScreen continue à l’appeler dans le même fichier. Si, plus tard, on déplace cet appel vers un autre fichier, il faudra revoir l’emplacement ou la visibilité en fonction du besoin.

Et une variable déclarée dans une fonction ?

Sa portée la limite déjà à son bloc. On ne met pas private ou public devant une variable locale comme isAnswerCorrect dans checkAnswer. Son emplacement et la portée étudiée plus tôt expliquent où son nom est accessible.

💡

Portée / visibilité

La portée dépend de l’endroit où le nom est déclaré. La visibilité ajoute une limite d’accès pour les déclarations concernées. Une variable locale n’a pas de modificateur private ou public.

💡

Au niveau du fichier · top-level

Une déclaration située en dehors des classes et des fonctions. Pour cette déclaration, private signifie « dans ce fichier seulement ».

05 / Deux limites utiles dans le quiz

Rends privés les détails inutiles à la vue.

Avec l’encadrant, garde d’abord la version du score et du recommencement dans Git. Prépare ta branche de travail, par exemple ab/preciser_visibilite.

  1. Dans QuizPresenter.kt, retrouve tous les appels à isCorrectAnswer. Après la leçon sur le score, cette méthode n’est appelée que par submitAnswer dans la même classe. Ajoute private devant sa déclaration.
  2. Sur getScore, tu peux écrire public explicitement pour lire l’intention. Cela ne change pas sa visibilité actuelle.
  3. Dans MainActivity.kt, ajoute private devant fun QuestionView. Garde son annotation @Composable et son corps.
  4. Ne change pas Question.kt. Conserve publiques les actions et lectures du presenter que la vue appelle.
QuizPresenter.kt complet après le changement
package fr.stageacademy.quiz

class QuizPresenter(private val questions: List<Question>) {
    private var currentQuestionIndex: Int = 0
    private var hasAnsweredCurrentQuestion: Boolean = false
    private var isCurrentAnswerCorrect: Boolean = false
    private var score: Int = 0

    public fun getScore(): Int {
        return score
    }

    fun getCurrentQuestionIndex(): Int {
        return currentQuestionIndex
    }

    fun isFinished(): Boolean {
        return currentQuestionIndex >= questions.size
    }

    fun getCurrentQuestion(): Question {
        return questions[currentQuestionIndex]
    }

    private fun isCorrectAnswer(
        question: Question,
        selectedAnswer: String,
    ): Boolean {
        val result: Boolean = selectedAnswer == question.correctAnswer
        return result
    }

    fun submitAnswer(selectedAnswer: String): Boolean {
        if (isFinished()) {
            return false
        }
        if (hasAnsweredCurrentQuestion) {
            return isCurrentAnswerCorrect
        }
        val question: Question = getCurrentQuestion()
        isCurrentAnswerCorrect = isCorrectAnswer(question, selectedAnswer)
        hasAnsweredCurrentQuestion = true
        if (isCurrentAnswerCorrect) {
            score = score + 1
        }
        return isCurrentAnswerCorrect
    }

    fun canGoToNextQuestion(): Boolean {
        return hasAnsweredCurrentQuestion
    }

    fun goToNextQuestion(): Unit {
        if (canGoToNextQuestion()) {
            currentQuestionIndex = currentQuestionIndex + 1
            hasAnsweredCurrentQuestion = false
            isCurrentAnswerCorrect = false
        }
    }

    fun restart(): Unit {
        currentQuestionIndex = 0
        hasAnsweredCurrentQuestion = false
        isCurrentAnswerCorrect = false
        score = 0
    }
}
QuestionView complète avec sa visibilité
@Composable
private fun QuestionView(
    question: Question,
    questionIndex: Int,
    presenter: QuizPresenter,
    onAnswerSubmitted: () -> Unit,
    onNextQuestion: () -> Unit,
) {
    var feedbackText: String by remember(presenter, questionIndex) {
        mutableStateOf("Choisis une réponse.")
    }
    var canGoToNextQuestion: Boolean by remember(presenter, questionIndex) {
        mutableStateOf(presenter.canGoToNextQuestion())
    }

    fun checkAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = presenter.submitAnswer(selectedAnswer)
        if (isAnswerCorrect) {
            feedbackText = "Bonne réponse !"
        } else {
            feedbackText = "Réponse incorrecte."
        }
        canGoToNextQuestion = presenter.canGoToNextQuestion()
        onAnswerSubmitted()
    }

    Column(
        verticalArrangement = Arrangement.spacedBy(12.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(text = question.text)
        for (choice: String in question.choices) {
            Button(
                onClick = { checkAnswer(choice) },
                enabled = !canGoToNextQuestion,
            ) {
                Text(text = choice)
            }
        }
        Text(text = feedbackText)
        Button(
            onClick = onNextQuestion,
            enabled = canGoToNextQuestion,
        ) {
            Text(text = "Question suivante")
        }
    }
}

WelcomeScreen et ses appels ne changent pas. Ce n’est pas un nouvel écran ni une nouvelle règle de score : tu précises quelles déclarations sont disponibles ailleurs.

Expérience accompagnée : essayer puis annuler un accès interdit

Dans WelcomeScreen, juste après la création du presenter, essaie temporairement presenter.score = 100. Observe le refus de l’IDE. Retire cette ligne avant de compiler ou de lancer.

Essaie ensuite temporairement d’appeler presenter.isCorrectAnswer(firstQuestion, "Git"). Après le passage en private, cet accès direct est lui aussi refusé. Retire la ligne et garde le chemin normal : submitAnswer.

Le refus aide à comprendre la limite. Ce n’est pas une raison pour rendre la propriété ou la méthode publique.

Une fonction peut devenir privée parce que les besoins ont changé.

Au début, la validation était appelée directement depuis la vue. Maintenant, submitAnswer gère l’enregistrement et le score. La comparaison devient un détail interne ; la vue passe par l’action qui applique toutes les règles.

💡

Accès autorisé

La vue demande submitAnswer pour enregistrer une réponse. Elle ne doit pas appeler seulement la comparaison si cela contourne l’enregistrement du premier choix et le score.

06 / Vérifier les accès et le comportement

Les limites changent, le quiz fonctionne pareil.

  1. Retire les lignes d’expérience volontairement incorrectes, puis compile et lance.
  2. Fais une partie : les points, la réponse unique et « Suivante » doivent fonctionner comme avant.
  3. À la fin, recommence et vérifie la remise à zéro.
  4. Montre une propriété privée, une méthode publique, une méthode privée et une fonction privée au niveau du fichier.
Question : deux fonctions dans le même fichier peuvent-elles lire score ?

Pas simplement parce qu’elles sont dans le même fichier. Score est privée dans QuizPresenter : seules les méthodes de cette classe y accèdent directement. La fonction extérieure passe par getScore ou les actions autorisées.

Question : peut-on appeler QuestionView depuis un autre fichier ?

Après ce changement, non : elle est privée au fichier MainActivity.kt. WelcomeScreen peut toujours l’appeler dans ce même fichier.
