Des boîtes pour les informations

Variables et types de base.

Pour préparer ton quiz, commence par ranger ses informations dans des boîtes nommées : une question, trois choix et la bonne réponse.

Cette idée se retrouve dans beaucoup de langages. Ici, nous allons l’écrire avec Kotlin.

01 / Une image pour comprendre

Une variable, c’est comme une boîte.

Imagine une boîte dans laquelle tu ranges une information. Tu écris un nom sur son étiquette pour pouvoir la retrouver et accéder à son contenu quand tu en as besoin.

Pour notre quiz, une boîte peut contenir le texte de la question. Son étiquette sera questionText, ce qui signifie « texte de la question ».

Dans le code, utiliser le nom questionText permet de retrouver cette phrase sans la réécrire à chaque endroit où on en a besoin.

💡

Variable · variable

Pense à une boîte qui porte un nom et contient une information. Cette image nous aide à commencer.

💡

Valeur · value

L’information à l’intérieur de la boîte. Ici, c’est la phrase de la question.

02 / Passer de l’image au code

Déclare ta première variable avec val.

En Kotlin, voici comment écrire notre boîte :

val questionText: String = "Quel outil garde l’historique du code ?"
val
Indique que l’on souhaite créer une variable : dans notre image, on crée une boîte.
questionText
Le nom sur son étiquette.
: String
Le type de la variable : ce que l’on a le droit de mettre dans cette boîte. Ici, du texte.
= "…"
La valeur : ce que l’on va mettre dans notre boîte, donc dans notre variable.

Lis la ligne ainsi : « Je déclare une boîte appelée questionText, qui accepte du texte, et j’y mets la phrase de la question. »

Les guillemets indiquent où le texte commence et où il se termine. Ils ne font pas partie de la phrase contenue dans la boîte.

Déclarer · declare

Créer une boîte nommée dans notre image. Dans ces exemples, on écrit val, puis le nom, le type et la valeur.

💡

String · texte

Le nom du type utilisé en Kotlin pour du texte. Respecte sa majuscule : String.

03 / Que peut-on mettre dedans ?

Le type indique le contenu autorisé.

On ne range pas toutes les informations de la même façon. Le type est l’étiquette qui indique ce que l’on a le droit de mettre dans la boîte : du texte, un entier, un nombre à virgule, ou vrai/faux.

String · du texte

val firstChoice: String = "Git"

Pour un énoncé, un choix ou un message. Le contenu s’écrit entre guillemets.

Int · un nombre entier

val questionNumber: Int = 1

Pour numéroter une question ou compter quelque chose. On écrit 1 sans guillemets. "1" serait du texte.

Double · un nombre à virgule

val timeLimitSeconds: Double = 30.5

Pour représenter une durée comme 30,5 secondes. En Kotlin, on écrit un point : 30.5, et non 30,5.

Boolean · vrai ou faux

val isHintEnabled: Boolean = false

Pour indiquer, par exemple, si un indice est activé. true signifie vrai, false signifie faux. Ces mots s’écrivent sans guillemets.

Ce sont les premiers types de base dont nous avons besoin. Pour les nombres et les booléens, tu entendras aussi le terme « types primitifs ».

À toi : pourquoi Int = "10" ne convient-il pas ?
val questionNumber: Int = "10"

La boîte annonce un entier, mais les guillemets fournissent du texte. Pour y mettre le nombre dix, il faut écrire 10 sans guillemets.

💡

Type · type

Ce que la boîte accepte. Une boîte Int attend un entier ; une boîte String attend du texte.

💡

Integer → Int

Integer signifie « entier ». Un entier n’a pas de partie après la virgule.

💡

Double

Un type utilisé ici pour les nombres à virgule, comme 30.5.

💡

Boolean · booléen

Une information qui vaut true ou false : vrai ou faux.

04 / Retrouver la bonne boîte

Un bon nom explique ce qu’on lit.

Avec trois lignes, tu peux encore te souvenir de tout. Avec beaucoup de code, un nom doit permettre de comprendre l’information sans devoir chercher partout.

Compare ces deux écritures du même contenu :

val x: String = "Git"

val correctAnswer: String = "Git"

x ne dit pas à quoi sert « Git ». correctAnswer annonce que l’on accède à la bonne réponse. Le contenu est le même, mais le deuxième nom explique son rôle.

Choisis le nom selon le rôle de l’information.

« Git » pourrait être un choix, une bonne réponse ou un titre. Nomme la boîte firstChoice, correctAnswer ou screenTitle selon ce qu’elle représente.

Nous écrivons les noms en anglais pour retrouver les habitudes d’autres projets. Le texte destiné au joueur reste en français. Pour les noms de nos variables, nous utilisons camelCase : une première lettre minuscule, puis une majuscule au début des mots suivants.

questionText
Texte de la question.
firstChoice, secondChoice, thirdChoice
Premier, deuxième et troisième choix.
correctAnswer
Bonne réponse.
questionNumber
Numéro de la question.
timeLimitSeconds
Durée limite en secondes. Le nom indique aussi l’unité.
isHintEnabled
Un indice est-il activé ?
À toi : quel nom donner à une boîte contenant le titre du quiz ?

quizTitle (« titre du quiz ») indique ce qu’on retrouvera dedans. text est moins précis ; a ne renseigne pas sur son rôle.

💡

Camel case · camelCase

Une façon d’écrire plusieurs mots dans un nom, sans espaces : correctAnswer, questionText.

💡

is…

Un nom commençant par is peut se lire comme une question à laquelle on répond par vrai ou faux. Is hint enabled ? → Un indice est-il activé ?

05 / Préparer les données du quiz

Une boîte par information.

Écris maintenant les informations de ta première question dans un brouillon texte conservé à côté de tes notes, hors du code Android. Ne les colle pas encore au hasard dans MainActivity.kt : cette page prépare les déclarations sans modifier l’écran. La page sur les fonctions donnera un petit programme de vérification, puis la page Compose indiquera leur emplacement dans l’app.

val questionText: String = "Quel outil garde l’historique du code ?"
val firstChoice: String = "Git"
val secondChoice: String = "Android"
val thirdChoice: String = "Compose"
val correctAnswer: String = "Git"

Il y a cinq boîtes, chacune avec son nom. firstChoice et correctAnswer contiennent toutes les deux « Git », mais leurs rôles sont différents : la première est une proposition, la seconde est la solution attendue.

Tu peux aussi décrire cette question avec les autres types :

val questionNumber: Int = 1
val timeLimitSeconds: Double = 30.5
val isHintEnabled: Boolean = false

Tu as décrit des informations. Écrire une durée ne lance pas un chronomètre, et écrire la bonne réponse ne la vérifie pas encore. Ces boîtes serviront quand nous écrirons les actions du quiz.

💡

Données · data

Les informations que le programme utilisera. Ici, l’énoncé, les choix et la bonne réponse sont les données de la question.

06 / À toi de jouer

Décris une question avec tes propres boîtes.

  1. Choisis une question sur Git ou sur l’IDE que tu viens de découvrir.
  2. Écris son énoncé, trois choix et la bonne réponse en reprenant les cinq noms de l’exemple. Garde les types explicites et les guillemets pour le texte.
  3. Montre à ton encadrant le nom, le type et la valeur sur chaque ligne.
  4. Pour t’entraîner aux autres types, indique le numéro de cette question, une durée avec une décimale et si un indice est activé.
Question : quelle différence entre questionText et "questionText" ?

Sans guillemets, questionText est le nom qui permet d’accéder à notre boîte. Entre guillemets, "questionText" est simplement le texte « questionText ».
