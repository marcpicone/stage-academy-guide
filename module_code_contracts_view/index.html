Décrire ce qu’on peut attendre d’une action

Contrats et interfaces.

La vue doit pouvoir envoyer une réponse, lire le score et avancer. Elle n’a pas besoin de connaître la façon dont le presenter garde ses informations.

Écris ce dont elle a besoin dans une interface, puis fais respecter ce contrat par QuizPresenter. Le quiz conserve ses règles et son affichage.

01 / Une promesse entre deux parties

Que peut attendre la vue ?

Un contrat décrit ce qu’une partie du programme propose et les règles de son utilisation. Pour chaque opération, nous devons comprendre ce qu’elle reçoit, ce qu’elle renvoie et son effet.

submitAnswer · envoyer une réponse
Reçoit un texte et renvoie le résultat de la première réponse enregistrée pour la question. Compte au plus un point et ne remplace pas une réponse déjà enregistrée.
goToNextQuestion · avancer
Ne fait rien tant qu’aucune réponse n’a été donnée. Sinon, avance et remet les informations de réponse à leur état initial.
getCurrentQuestion · lire la question
S’utilise seulement lorsque le quiz n’est pas terminé. La vue vérifie isFinished avant de demander cette lecture.
restart · recommencer
Revient au début et remet le score ainsi que les informations de réponse à zéro.

La vue s’appuie sur ces promesses. Si avancer sautait parfois deux questions, elle ne pourrait plus utiliser cette action de façon fiable, même si les types étaient corrects.

💡

Contrat · contract

Ce qu’une partie du programme promet de fournir, avec les conditions d’utilisation et les résultats attendus.

💡

Condition d’utilisation · precondition

Ce qui doit être vrai avant une action. Exemple : le quiz ne doit pas être terminé avant getCurrentQuestion.

02 / Écrire les opérations disponibles

Une interface décrit les signatures.

Crée un fichier QuizContract.kt dans le même dossier et le même package que QuizPresenter.kt :

package fr.stageacademy.quiz

interface QuizContract {
    fun getScore(): Int
    fun getCurrentQuestionIndex(): Int
    fun isFinished(): Boolean
    fun getCurrentQuestion(): Question
    fun submitAnswer(selectedAnswer: String): Boolean
    fun canGoToNextQuestion(): Boolean
    fun goToNextQuestion(): Unit
    fun restart(): Unit
}

interface déclare ici un type qui décrit les opérations attendues. Nous écrivons uniquement leurs signatures : nom, paramètres et type de retour. Il n’y a pas de corps de méthode dans ce contrat.

La vue utilise ces huit opérations. La comparaison privée isCorrectAnswer ne figure pas dans l’interface : c’est un détail de l’implémentation.

Une interface Kotlin peut aussi proposer certaines méthodes avec un corps. Nous n’en avons pas besoin ici : nous séparons volontairement la description des opérations et leur réalisation.

Le contrat décrit ce qu’on peut demander, pas comment le travail est fait.

Il ne déclare ni score privé, ni indice privé, ni code de comptage. Une classe va fournir ces détails.

💡

Interface · interface

Un type qui décrit ici les opérations qu’une implémentation doit fournir. Ce mot ne désigne pas l’interface graphique de l’application.

💡

Signature · signature

Le nom d’une fonction, ses paramètres et son type de retour : la forme de l’appel autorisé.

💡

QuizContract

« Contrat du quiz ». Comme pour une classe, le nom de ce type commence par une majuscule.

03 / Fournir le code promis

QuizPresenter implémente le contrat.

La classe annonce l’interface qu’elle réalise après le signe : :

class QuizPresenter(private val questions: List<Question>) : QuizContract {
    // Les méthodes sont fournies dans cette classe.
}

Elle place le mot-clé override devant chaque méthode déclarée dans QuizContract. Exemple :

override fun getScore(): Int {
    return score
}

Override indique que cette méthode fournit l’opération annoncée par le contrat. Le nom, les paramètres et le retour doivent correspondre. Le compilateur vérifie que cette classe concrète fournit toutes les méthodes nécessaires.

QuizPresenter.kt complet avec les huit méthodes du contrat
package fr.stageacademy.quiz

class QuizPresenter(private val questions: List<Question>) : QuizContract {
    private var currentQuestionIndex: Int = 0
    private var hasAnsweredCurrentQuestion: Boolean = false
    private var isCurrentAnswerCorrect: Boolean = false
    private var score: Int = 0

    override fun getScore(): Int {
        return score
    }

    override fun getCurrentQuestionIndex(): Int {
        return currentQuestionIndex
    }

    override fun isFinished(): Boolean {
        return currentQuestionIndex >= questions.size
    }

    override fun getCurrentQuestion(): Question {
        return questions[currentQuestionIndex]
    }

    private fun isCorrectAnswer(
        question: Question,
        selectedAnswer: String,
    ): Boolean {
        val result: Boolean = selectedAnswer == question.correctAnswer
        return result
    }

    override fun submitAnswer(selectedAnswer: String): Boolean {
        if (isFinished()) {
            return false
        }
        if (hasAnsweredCurrentQuestion) {
            return isCurrentAnswerCorrect
        }
        val question: Question = getCurrentQuestion()
        isCurrentAnswerCorrect = isCorrectAnswer(question, selectedAnswer)
        hasAnsweredCurrentQuestion = true
        if (isCurrentAnswerCorrect) {
            score = score + 1
        }
        return isCurrentAnswerCorrect
    }

    override fun canGoToNextQuestion(): Boolean {
        return hasAnsweredCurrentQuestion
    }

    override fun goToNextQuestion(): Unit {
        if (canGoToNextQuestion()) {
            currentQuestionIndex = currentQuestionIndex + 1
            hasAnsweredCurrentQuestion = false
            isCurrentAnswerCorrect = false
        }
    }

    override fun restart(): Unit {
        currentQuestionIndex = 0
        hasAnsweredCurrentQuestion = false
        isCurrentAnswerCorrect = false
        score = 0
    }
}

Le corps des méthodes ne change pas. Les propriétés restent privées et isCorrectAnswer reste privée. Les méthodes du contrat restent publiques ; on ne peut pas promettre une opération utilisable puis la rendre privée dans cette implémentation.

💡

Implémentation · implementation

Le code qui réalise les opérations promises. Ici, QuizPresenter implémente QuizContract.

💡

override

Le mot-clé qui relie la méthode de la classe à l’opération décrite par l’interface.

💡

Classe concrète

Une classe dont on peut créer une instance ici, comme QuizPresenter. L’interface seule ne fournit pas le fonctionnement du quiz.

04 / Utiliser le contrat comme type

La vue reçoit ce dont elle a besoin.

Dans WelcomeScreen, le type de la variable change, mais la création reste explicite :

val presenter: QuizContract = remember(questions) { QuizPresenter(questions) }

À gauche, QuizContract indique les opérations que le code pourra utiliser. À droite, QuizPresenter(questions) crée l’objet concret qui les réalisera. L’objet n’est pas transformé : il est utilisable sous le type de son interface.

Dans les paramètres de QuestionView, remplace aussi presenter: QuizPresenter par presenter: QuizContract. Les appels submitAnswer, getScore ou restart gardent la même forme.

QuestionView complète dépendant du contrat
@Composable
private fun QuestionView(
    question: Question,
    questionIndex: Int,
    presenter: QuizContract,
    onAnswerSubmitted: () -> Unit,
    onNextQuestion: () -> Unit,
) {
    var feedbackText: String by remember(presenter, questionIndex) {
        mutableStateOf("Choisis une réponse.")
    }
    var canGoToNextQuestion: Boolean by remember(presenter, questionIndex) {
        mutableStateOf(presenter.canGoToNextQuestion())
    }

    fun checkAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = presenter.submitAnswer(selectedAnswer)
        if (isAnswerCorrect) {
            feedbackText = "Bonne réponse !"
        } else {
            feedbackText = "Réponse incorrecte."
        }
        canGoToNextQuestion = presenter.canGoToNextQuestion()
        onAnswerSubmitted()
    }

    Column(
        verticalArrangement = Arrangement.spacedBy(12.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(text = question.text)
        for (choice: String in question.choices) {
            Button(
                onClick = { checkAnswer(choice) },
                enabled = !canGoToNextQuestion,
            ) {
                Text(text = choice)
            }
        }
        Text(text = feedbackText)
        Button(
            onClick = onNextQuestion,
            enabled = canGoToNextQuestion,
        ) {
            Text(text = "Question suivante")
        }
    }
}
WelcomeScreen complet
@Composable
fun WelcomeScreen(modifier: Modifier = Modifier) {
    val firstQuestion: Question = Question(
        text = "Quel outil garde l’historique du code ?",
        choices = listOf("Git", "Android", "Compose"),
        correctAnswer = "Git",
    )

    val secondQuestion: Question = Question(
        text = "Quel composant Compose affiche du texte ?",
        choices = listOf("Button", "Text", "Column"),
        correctAnswer = "Text",
    )

    val thirdQuestion: Question = Question(
        text = "Quel mot-clé déclare une fonction en Kotlin ?",
        choices = listOf("fun", "val", "if"),
        correctAnswer = "fun",
    )

    val fourthQuestion: Question = Question(
        text = "Quel type représente vrai ou faux ?",
        choices = listOf("String", "Boolean", "Int"),
        correctAnswer = "Boolean",
    )

    val questions: List<Question> = listOf(
        firstQuestion,
        secondQuestion,
        thirdQuestion,
        fourthQuestion,
    )
    val presenter: QuizContract = remember(questions) { QuizPresenter(questions) }
    var displayedQuestionIndex: Int by remember(presenter) {
        mutableStateOf(presenter.getCurrentQuestionIndex())
    }
    var isQuizFinished: Boolean by remember(presenter) {
        mutableStateOf(presenter.isFinished())
    }
    var displayedScore: Int by remember(presenter) {
        mutableStateOf(presenter.getScore())
    }

    Column(
        modifier = modifier
            .fillMaxSize()
            .verticalScroll(rememberScrollState())
            .padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(24.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(
            text = stringResource(R.string.welcome_title),
            style = MaterialTheme.typography.headlineMedium,
        )
        Text(text = "Score : $displayedScore / ${questions.size}")
        if (isQuizFinished) {
            Text(text = "Quiz terminé")
            Button(onClick = {
                presenter.restart()
                displayedQuestionIndex = presenter.getCurrentQuestionIndex()
                isQuizFinished = presenter.isFinished()
                displayedScore = presenter.getScore()
            }) {
                Text(text = "Recommencer")
            }
        } else {
            Text(text = "Question ${displayedQuestionIndex + 1}")
            val question: Question = presenter.getCurrentQuestion()
            QuestionView(
                question = question,
                questionIndex = displayedQuestionIndex,
                presenter = presenter,
                onAnswerSubmitted = {
                    displayedScore = presenter.getScore()
                },
                onNextQuestion = {
                    presenter.goToNextQuestion()
                    displayedQuestionIndex = presenter.getCurrentQuestionIndex()
                    isQuizFinished = presenter.isFinished()
                },
            )
        }
    }
}

QuestionView ne crée pas elle-même le presenter. WelcomeScreen choisit l’implémentation et la transmet. Plus tard, une autre classe qui respecte ce contrat pourrait être fournie à cette vue sans changer ses appels.

Peut-on écrire QuizContract() pour créer le quiz ?

Non. Cette interface décrit les opérations, mais elle n’est pas une classe concrète à construire ici. On crée QuizPresenter(questions), puis on peut conserver cet objet dans une variable de type QuizContract.

💡

Dépendre du contrat

Écrire les appels avec le type QuizContract. La vue utilise ses opérations, sans demander les détails propres à QuizPresenter.

💡

Même objet, type différent

La variable presenter désigne toujours l’instance créée par QuizPresenter(questions). Son type déclaré montre seulement ce que le code peut lui demander.

05 / Ce que le compilateur garantit

Une bonne signature ne suffit pas.

Si QuizPresenter oublie restart ou lui donne un retour incompatible, le compilateur refuse cette implémentation. C’est une aide pour conserver la forme des échanges.

En revanche, une méthode restart vide peut avoir la bonne signature et compiler sans remettre le score à zéro. La promesse de comportement doit donc être expliquée et vérifiée avec des tests.

Vérifié par le compilateur
Les méthodes nécessaires, leurs paramètres et les types de retour compatibles.
À expliquer et tester
Le premier choix définitif, le comptage unique, le passage après réponse, la fin et la remise à zéro.
À toi : getCurrentQuestion est dans le contrat. Puis-je l’appeler après la fin ?

Non : la présence de la méthode n’annule pas sa condition d’utilisation. La vue continue de vérifier isFinished avant la lecture. Le contrat inclut aussi cette règle, même si la signature seule ne l’exprime pas.

Une interface ajoute un fichier et des noms à comprendre. Nous l’utilisons ici pour rendre visibles les échanges entre vue et presenter. Il n’est pas nécessaire de créer une interface pour chaque classe : un contrat doit correspondre à un besoin, pas seulement à une habitude.

💡

Respecter le contrat

Fournir la bonne forme d’opération et le comportement promis. Les deux sont nécessaires.

💡

Remplaçable · replaceable

Une autre implémentation ne doit pas seulement avoir les mêmes méthodes : elle doit aussi respecter les attentes de ceux qui l’utilisent.

06 / Appliquer sans changer le quiz

Relie le contrat, la classe et la vue.

  1. Avec l’encadrant, garde la version précédente dans Git puis prépare une branche comme ab/definir_contrat_quiz.
  2. Ajoute QuizContract.kt à côté de Question.kt et QuizPresenter.kt, avec la même ligne package.
  3. Fais implémenter QuizContract par QuizPresenter et ajoute override aux huit méthodes. Garde isCorrectAnswer privée et hors du contrat.
  4. Dans MainActivity.kt, utilise QuizContract comme type de la variable presenter et du paramètre de QuestionView. Garde QuestionView privée au fichier.
  5. Compile, puis vérifie une partie et le recommencement. Les règles et les résultats doivent rester identiques.
Expérience avec l’encadrant : observer une promesse manquante

Retire temporairement la méthode restart de QuizPresenter, sans la retirer du contrat. Observe le message indiquant que la classe ne fournit pas une opération requise. Restaure ensuite sa méthode complète avant de compiler et de lancer.

Essaie aussi de retirer seulement override sur getScore : l’IDE demande de rétablir le lien avec la méthode du contrat. Restaure le code, sans supprimer l’opération de l’interface pour contourner le message.

Quel fichier modifier pour chaque besoin ?

Changer le comptage sans modifier les opérations disponibles : QuizPresenter.kt. Décrire une nouvelle opération attendue : QuizContract.kt, puis son implémentation et ses appels. Modifier le texte d’un message affiché : QuestionView dans MainActivity.kt.
