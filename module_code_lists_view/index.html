Moins de noms, plus de choix

Regrouper les choix dans une liste.

Tu as trois choix et trois boutons par question. Au lieu de leur donner chacun un nom, rassemble-les dans une liste et décris une seule fois comment afficher un choix.

Objectif : ajouter un quatrième choix en modifiant les données, sans recopier un bouton ni une nouvelle action.

01 / Partir de la répétition

Ces valeurs appartiennent au même groupe.

À la page précédente, la première question avait ces trois déclarations :

val firstQuestionFirstChoice: String = "Git"
val firstQuestionSecondChoice: String = "Android"
val firstQuestionThirdChoice: String = "Compose"

Elles décrivent toutes des choix de la même question. Un quatrième choix demanderait un nouveau nom, un nouveau bouton et de nouveaux liens à vérifier. Une liste permet de garder plusieurs choix sous un nom commun : firstQuestionChoices.

Avec l’encadrant, repars de tes deux questions fonctionnelles et garde cette étape dans Git. Prépare ta branche de travail avant les modifications, par exemple ab/regrouper_les_choix.

💡

Structure de données · data structure

Une façon d’organiser des informations pour les retrouver et les utiliser. La liste est notre premier exemple.

💡

Choices · choix

Le pluriel indique que ce nom représente plusieurs choix, et non un seul texte.

02 / Un nom pour plusieurs éléments

Déclare une List de String.

Pour la première question, remplace les trois déclarations de choix par :

val firstQuestionChoices: List<String> = listOf(
    "Git",
    "Android",
    "Compose",
)
firstQuestionChoices
Le nom du groupe : les choix de la première question.
List<String>
Le type de la variable : une liste dont les éléments sont des textes.
listOf(…)
L’appel qui crée la liste avec les valeurs indiquées entre parenthèses, séparées par des virgules.

Une liste conserve l’ordre de ses éléments. Ici, Git vient avant Android, puis Compose. Chaque élément est une valeur ; on ne crée plus trois noms de variables différents.

Nous utilisons la liste en lecture : nous ne lui ajoutons pas d’élément pendant que l’application fonctionne. Pour l’exercice, nous modifierons les valeurs écrites dans le code, puis nous relancerons.

Une liste remplace-t-elle aussi la question et sa bonne réponse ?

Pas dans cette étape. firstQuestionText reste un texte, et firstQuestionCorrectAnswer reste la bonne réponse. Notre liste regroupe uniquement les choix. Nous apprendrons ensuite à réunir les informations qui décrivent une question.

💡

List · liste

Un groupe ordonné d’éléments. Une même valeur peut apparaître plusieurs fois dans une liste.

💡

Élément · element / item

Une valeur dans la liste. Git est ici le premier élément.

💡

Les signes < et >

Dans List<String>, ils précisent le type des éléments. Ce ne sont pas des signes de comparaison à cet endroit.

03 / Retrouver un élément

La première position porte le numéro 0.

Pour accéder à un élément précis, on utilise son indice entre crochets :

val firstChoice: String = firstQuestionChoices[0]
val choiceCount: Int = firstQuestionChoices.size

firstChoice reçoit « Git » et choiceCount reçoit 3. Le point dans .size permet ici de lire le nombre d’éléments de la liste.

  1. Indice 0Git
  2. Indice 1Android
  3. Indice 2Compose

Cette liste a trois éléments, mais pas d’élément à l’indice 3. Y accéder avec firstQuestionChoices[3] provoquerait une erreur pendant l’exécution. Ces deux lignes sont un exemple de lecture : nous n’avons pas besoin de les ajouter à l’écran pour générer les boutons.

À toi : que contient firstQuestionChoices[1] ?

« Android », le deuxième élément. Le numéro affiché dans le langage commence à zéro, pas à un.

💡

Indice · index

Le numéro de position d’un élément dans une liste. Le premier indice est 0.

💡

Size · taille

Le nombre d’éléments. Une taille de 3 correspond aux indices 0, 1 et 2.

💡

Crochets · brackets

Les signes [ et ] utilisés ici pour demander un élément par son indice.

04 / Répéter une action pour chaque élément

Une boucle pour les boutons.

Nous voulons appliquer la même description à tous les choix : un bouton qui affiche ce choix et le transmet à l’action de validation. La boucle for permet de parcourir les éléments :

for (choice: String in firstQuestionChoices) {
    Button(onClick = { checkFirstAnswer(choice) }) {
        Text(text = choice)
    }
}

Lis la première ligne ainsi : « Pour chaque texte choice dans firstQuestionChoices, décris ce bouton. »

  1. Premier passage : choice contient « Git ».
  2. Deuxième passage : choice contient « Android ».
  3. Troisième passage : choice contient « Compose ».
  4. Il n’y a plus d’élément : le parcours se termine.

choice est le nom local utilisé dans le corps de la boucle pour l’élément courant. Chaque bouton affiche cet élément et le fournit à checkFirstAnswer lorsqu’on clique dessus.

Décrire les boutons et cliquer sont deux moments différents.

Compose parcourt la liste pour décrire les boutons. Le bloc onClick garde l’action pour plus tard : la boucle ne répond pas automatiquement à la question.

Remplace les trois boutons de la première question par ce parcours. Pour la deuxième, utilise la même forme avec secondQuestionChoices et checkSecondAnswer.

💡

Boucle · loop

Une instruction qui répète un bloc de code. Ici, for le fait une fois pour chaque élément de la liste.

💡

for / in

« Pour chaque … dans … ». La liste indique les éléments à parcourir.

💡

Portée de choice

Le nom choice est accessible dans le corps de cette boucle, y compris le bloc du bouton. Une autre boucle peut avoir son propre choice.

Comparer avec la version complète de WelcomeScreen

Cette version reprend le cadre de la page précédente. Les changements concernent uniquement les listes de choix et les deux parcours qui décrivent les boutons.

@Composable
fun WelcomeScreen(modifier: Modifier = Modifier) {
    val firstQuestionText: String = "Quel outil garde l’historique du code ?"
    val firstQuestionChoices: List<String> = listOf(
        "Git",
        "Android",
        "Compose",
    )
    val firstQuestionCorrectAnswer: String = "Git"

    val secondQuestionText: String = "Quel composant Compose affiche du texte ?"
    val secondQuestionChoices: List<String> = listOf(
        "Button",
        "Text",
        "Column",
    )
    val secondQuestionCorrectAnswer: String = "Text"

    var firstFeedbackText: String by remember {
        mutableStateOf("Choisis une réponse pour la question 1.")
    }
    var secondFeedbackText: String by remember {
        mutableStateOf("Choisis une réponse pour la question 2.")
    }

    fun checkFirstAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = isCorrectAnswer(
            selectedAnswer,
            firstQuestionCorrectAnswer,
        )
        if (isAnswerCorrect) {
            firstFeedbackText = "Bonne réponse !"
        } else {
            firstFeedbackText = "Essaie encore."
        }
    }

    fun checkSecondAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = isCorrectAnswer(
            selectedAnswer,
            secondQuestionCorrectAnswer,
        )
        if (isAnswerCorrect) {
            secondFeedbackText = "Bonne réponse !"
        } else {
            secondFeedbackText = "Essaie encore."
        }
    }

    Column(
        modifier = modifier
            .fillMaxSize()
            .verticalScroll(rememberScrollState())
            .padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(16.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(
            text = stringResource(R.string.welcome_title),
            style = MaterialTheme.typography.headlineMedium,
        )
        Text(text = "Question 1", style = MaterialTheme.typography.titleMedium)
        Text(text = firstQuestionText)
        for (choice: String in firstQuestionChoices) {
            Button(onClick = { checkFirstAnswer(choice) }) {
                Text(text = choice)
            }
        }
        Text(text = firstFeedbackText)
        Text(text = "Question 2", style = MaterialTheme.typography.titleMedium)
        Text(text = secondQuestionText)
        for (choice: String in secondQuestionChoices) {
            Button(onClick = { checkSecondAnswer(choice) }) {
                Text(text = choice)
            }
        }
        Text(text = secondFeedbackText)
    }
}

List et listOf sont disponibles en Kotlin sans import supplémentaire dans cet exemple. Le défilement utilise toujours les deux imports ajoutés à la page précédente.

L’IDE ne retrouve plus firstQuestionFirstChoice

Ce nom a été retiré lorsque tu as remplacé les trois variables par une liste. Recherche ses utilisations restantes dans WelcomeScreen. Dans les boutons, la boucle doit maintenant utiliser choice. Évite de recréer les anciennes variables pour masquer une utilisation oubliée.

💡

Conserver le comportement

Le joueur doit obtenir les mêmes réponses qu’avant. Nous changeons la manière d’organiser les choix et de les afficher, pas la règle qui décide si une réponse est correcte.

06 / Une nouvelle possibilité

Ajoute un choix sans recopier de bouton.

  1. Teste les six choix : Git est correct pour la première question, Text pour la deuxième. Les autres choix donnent « Essaie encore. » et les messages restent indépendants.
  2. Dans firstQuestionChoices, ajoute le texte "Logcat" comme quatrième élément. Ne modifie ni la boucle ni l’action de validation.
  3. Relance : un quatrième bouton « Logcat » doit apparaître pour la première question. Son clic donne « Essaie encore. ».
  4. Déplace « Git » à la fin de la liste et relance. Il doit être affiché en dernier et rester la bonne réponse.

Nous comparons le texte choisi avec la bonne réponse, pas sa position. Changer l’ordre ne doit donc pas changer la validation.

Pourquoi le nouveau bouton existe-t-il sans nouveau code de bouton ?

La boucle décrit un bouton pour chaque élément de la liste. Ajouter un élément dans les données ajoute donc un passage lors de la prochaine description de l’écran après relance.

Qu’est-ce qui se répète encore entre les deux questions ?

Chaque question a toujours son propre énoncé, sa liste de choix, sa bonne réponse et son message. Les deux actions et les deux groupes d’affichage ont encore une forme semblable. Les listes ont résolu un premier problème, mais nous devons encore organiser les informations de chaque question.
