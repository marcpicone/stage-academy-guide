01 / Décrire ce que le joueur voit

Une première vue avec Compose.

Compose permet de décrire l’interface Android en Kotlin. Une fonction marquée @Composable peut décrire des éléments d’écran. Dans notre projet, c’est le rôle de WelcomeScreen, déjà appelée par le code de départ.

Text · afficher du texte

Text(text = questionText)

Le paramètre text reçoit la phrase à afficher. Ici, nous transmettons la valeur de notre variable questionText.

Column · placer à la verticale

Column {
    Text(text = questionText)
    Text(text = firstChoice)
}

Les éléments décrits entre les accolades se placent les uns sous les autres.

Button · proposer une action

Un bouton contient un libellé visible et reçoit une action à effectuer au clic. Nous allons utiliser un Text pour son libellé.

Dans les exemples fournis, Modifier règle la taille ou les marges, et MaterialTheme fournit un style de texte. Garde ces réglages pour cette étape : nous allons d’abord relier les données et les actions.

💡

Interface / vue · UI / view

Ce que le joueur voit et utilise : textes, boutons et leur disposition.

💡

Composable

Une fonction signalée par @Composable, utilisée ici pour décrire une partie de l’interface. Notre fonction de validation reste une fonction Kotlin ordinaire.

💡

Composant · component

Un élément réutilisable de l’interface, comme Text ou Button.

02 / Un bouton, une action

Qu’exécute le clic ?

Voici le bouton du premier choix :

Button(onClick = { checkAnswer(firstChoice) }) {
    Text(text = firstChoice)
}

Text(text = firstChoice) affiche « Git ». onClick reçoit le bloc d’action { checkAnswer(firstChoice) }. Ce bloc sera exécuté quand le joueur cliquera, pas quand le bouton est décrit.

checkAnswer sera notre action qui demande la validation puis choisit le message. Le même nom de variable sert ici à afficher le choix et à transmettre sa valeur au clic : on vérifie bien ce que le joueur a choisi.

Les deux autres boutons utiliseront exactement le même principe avec secondChoice et thirdChoice.

💡

onClick · au clic

Le paramètre qui reçoit l’action à exécuter quand le bouton est activé.

💡

Bloc d’action · lambda

Une action écrite entre accolades et transmise à une autre fonction. Ici, le bouton la garde pour le clic. Nous n’avons besoin que de cet usage pour commencer.

03 / Utiliser le résultat de validation

Si la réponse est correcte… sinon…

isCorrectAnswer renvoie true ou false. Pour choisir ce qui se passe selon ce résultat, on utilise une condition :

if (isAnswerCorrect) {
    feedbackText = "Bonne réponse !"
} else {
    feedbackText = "Essaie encore."
}

if signifie « si » : si isAnswerCorrect vaut true, on exécute le premier bloc. else signifie « sinon » : si la valeur est false, on exécute le deuxième. Un seul des deux messages est choisi pour cet appel.

Voici l’action complète, à lire avant de l’intégrer à l’écran :

fun checkAnswer(selectedAnswer: String): Unit {
    val isAnswerCorrect: Boolean = isCorrectAnswer(selectedAnswer, correctAnswer)
    if (isAnswerCorrect) {
        feedbackText = "Bonne réponse !"
    } else {
        feedbackText = "Essaie encore."
    }
}

Elle reçoit le choix, appelle notre règle de validation, puis change le message. Son retour est Unit : son rôle est de mettre à jour ce message, pas de fournir un nouveau résultat à récupérer.

💡

Condition · condition

Une question vraie ou fausse qui permet de choisir quelle action exécuter.

💡

feedbackText

Le « texte de retour au joueur » : le message qui lui indique le résultat de son choix.

💡

isAnswerCorrect

« La réponse est-elle correcte ? » : le résultat Boolean de notre validation.

04 / Une information qui évolue

Quand garder val, quand utiliser var ?

Les textes des choix ne changent pas pendant cet exercice : val convient. Le message doit au contraire être remplacé après un clic : nous utilisons var.

var feedbackText: String by remember {
    mutableStateOf("Choisis une réponse.")
}

Plus tard, feedbackText = "Bonne réponse !" donne un nouveau texte à la même variable. On ne remet pas var devant son nom : la variable existe déjà.

La différence répond à un besoin : val pour une valeur qu’on ne réaffecte pas ; var quand le programme doit la remplacer. Son type reste String : on remplace un texte par un autre texte.

var autorise un changement ; l’état Compose rend ce changement visible.

Un simple var feedbackText: String = "…" ne suffit pas à demander à Compose de mettre à jour l’écran au clic. Le petit cadre ci-dessus est nécessaire dans cet exemple.

  • mutableStateOf crée une valeur observée par Compose. Quand elle change, Compose peut mettre à jour les éléments qui la lisent.
  • remember conserve cette valeur entre les nouvelles descriptions de cette même vue à l’écran.
  • by, avec les imports fournis, permet de lire et modifier cet état en utilisant directement feedbackText.

Nous affichons la valeur avec Text(text = feedbackText). Le message change quand l’état change. remember n’est pas une sauvegarde durable : un redémarrage de l’activité, par exemple après une rotation, peut remettre le message initial.

💡

État · state

Une information qui peut évoluer et dont l’affichage dépend. Ici, c’est le message après la réponse.

💡

Réaffecter · reassign

Remplacer la valeur d’une variable existante pendant le fonctionnement du programme. Dans notre exemple, cela demande var.

💡

Recomposition

Compose décrit à nouveau les parties concernées de l’interface pour tenir compte des valeurs observées qui ont changé.

fun isCorrectAnswer(
    selectedAnswer: String,
    correctAnswer: String,
): Boolean {
    val result: Boolean = selectedAnswer == correctAnswer
    return result
}
@Composable
fun WelcomeScreen(modifier: Modifier = Modifier) {
    val questionText: String = "Quel outil garde l’historique du code ?"
    val firstChoice: String = "Git"
    val secondChoice: String = "Android"
    val thirdChoice: String = "Compose"
    val correctAnswer: String = "Git"

    var feedbackText: String by remember {
        mutableStateOf("Choisis une réponse.")
    }

    fun checkAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = isCorrectAnswer(selectedAnswer, correctAnswer)
        if (isAnswerCorrect) {
            feedbackText = "Bonne réponse !"
        } else {
            feedbackText = "Essaie encore."
        }
    }

    Column(
        modifier = modifier.fillMaxSize().padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(16.dp, Alignment.CenterVertically),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(
            text = stringResource(R.string.welcome_title),
            style = MaterialTheme.typography.headlineMedium,
        )
        Text(text = questionText)
        Button(onClick = { checkAnswer(firstChoice) }) {
            Text(text = firstChoice)
        }
        Button(onClick = { checkAnswer(secondChoice) }) {
            Text(text = secondChoice)
        }
        Button(onClick = { checkAnswer(thirdChoice) }) {
            Text(text = thirdChoice)
        }
        Text(text = feedbackText)
    }
}
Les imports nécessaires pour l’état et le bouton

Ces imports sont déjà présents dans le projet de départ avec le bouton « Click me ». S’ils manquent dans ton fichier, ajoute uniquement ceux qui ne sont pas déjà en haut du fichier :

import androidx.compose.material3.Button
import androidx.compose.runtime.getValue
import androidx.compose.runtime.mutableStateOf
import androidx.compose.runtime.remember
import androidx.compose.runtime.setValue

Les autres éléments de la vue reprennent les imports de l’écran de départ : Text, Column, Modifier, Composable, les espacements et le thème.

Le bouton « Click me » est maintenant remplacé par les trois boutons de réponse. Les paramètres de disposition de Column et le titre reprennent le cadre existant. Les valeurs de durée, d’indice ou de numéro de question ne sont pas nécessaires à ce premier écran.

Pourquoi checkAnswer est-elle à l’intérieur de WelcomeScreen ?

C’est une action locale, utilisée uniquement par cet écran. Elle peut lire correctAnswer et changer feedbackText déclarés dans le bloc qui l’entoure. Les trois boutons du même écran peuvent l’appeler. isCorrectAnswer, définie au niveau du fichier, reste indépendante et reçoit les deux textes nécessaires à sa règle.

On utilise ainsi la portée étudiée à la page précédente. Nous séparerons davantage les responsabilités quand le quiz grandira.

💡

Import

Une ligne qui rend disponible un nom fourni ailleurs. Ici, les outils Compose viennent des bibliothèques déjà présentes dans le projet.

💡

Logique / affichage

isCorrectAnswer applique la règle ; Text et Button décrivent l’écran. checkAnswer fait ici le lien entre le choix, la règle et le message.

L’action est réutilisable. Chaque bouton lui fournit une valeur différente : secondChoice ou firstChoice. La règle reçoit ce choix, puis le résultat décide du message.
