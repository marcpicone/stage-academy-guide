01 / Donner une place à chaque fiche

Pourquoi un pager plutôt qu’une rangée de cartes ?

Dans une LazyRow, tu parcours librement les cartes. Pour réviser une question à la fois, tu peux préférer une présentation qui se cale sur une page après le geste.

Un pager sert à parcourir des pages de contenu. Dans notre révision, chaque page contient une question et sa bonne réponse. Le joueur peut avancer et revenir librement, sans donner de réponse ni gagner de point.

Une autre façon de consulter, pas une nouvelle règle de jeu.

Le pager remplace la présentation de la révision après le résultat. Il ne pilote pas l’indice de question du presenter et ne remplace pas « Question suivante » pendant la partie.

Tu rencontreras le nom ViewPager dans des projets utilisant le système de vues Android. En Compose, nous utilisons HorizontalPager ; VerticalPager existe pour le défilement vertical. La documentation Android présente ces composants.

03 / Un état pour la position de lecture

Remplace seulement la vue de révision.

Dans ton clone, remplace uniquement ReviewScreen et son annotation par l’exemple complet ci-dessous. Garde ReviewCard, les données et le branchement depuis le résultat. Ne conserve pas l’ancienne liste ou grille dans cette fonction.

Ajoute les imports manquants ; ceux de Modifier, des composants de base et des dimensions sont déjà présents dans la version de la page sur les listes.

import androidx.compose.foundation.layout.Row
import androidx.compose.foundation.pager.HorizontalPager
import androidx.compose.foundation.pager.rememberPagerState
import androidx.compose.foundation.rememberScrollState
import androidx.compose.foundation.verticalScroll
import androidx.compose.runtime.rememberCoroutineScope
import kotlinx.coroutines.launch
ReviewScreen complète avec le pager
@Composable
private fun ReviewScreen(
    questions: List<Question>,
    onBack: () -> Unit,
    modifier: Modifier = Modifier,
) {
    val pagerState = rememberPagerState(pageCount = { questions.size })
    val coroutineScope = rememberCoroutineScope()

    Column(
        modifier = modifier.fillMaxSize().padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(16.dp),
    ) {
        Text(text = "Réviser les questions")
        Button(onClick = onBack) {
            Text(text = "Retour au résultat")
        }
        if (questions.isEmpty()) {
            Text(text = "Aucune question à réviser.")
        } else {
            Text(text = "Fiche ${pagerState.currentPage + 1} / ${questions.size}")
            HorizontalPager(
                state = pagerState,
                modifier = Modifier.weight(1f).fillMaxWidth(),
                pageSpacing = 16.dp,
                verticalAlignment = Alignment.Top,
            ) { page: Int ->
                Column(
                    modifier = Modifier.fillMaxSize()
                        .verticalScroll(rememberScrollState()),
                ) {
                    ReviewCard(question = questions[page])
                }
            }
            Row(
                modifier = Modifier.fillMaxWidth(),
                horizontalArrangement = Arrangement.spacedBy(16.dp),
            ) {
                Button(
                    onClick = {
                        coroutineScope.launch {
                            pagerState.animateScrollToPage(pagerState.currentPage - 1)
                        }
                    },
                    enabled = pagerState.currentPage > 0 && !pagerState.isScrollInProgress,
                    modifier = Modifier.weight(1f),
                ) {
                    Text(text = "Précédente")
                }
                Button(
                    onClick = {
                        coroutineScope.launch {
                            pagerState.animateScrollToPage(pagerState.currentPage + 1)
                        }
                    },
                    enabled = pagerState.currentPage < questions.lastIndex
                        && !pagerState.isScrollInProgress,
                    modifier = Modifier.weight(1f),
                ) {
                    Text(text = "Suivante")
                }
            }
        }
    }
}

rememberPagerState conserve l’état de navigation pendant les mises à jour de cette vue. pageCount fournit le nombre de pages, ici la taille de la liste.

Le bloc du pager reçoit l’indice page. questions[page] fournit la donnée à afficher. Le numéro lu par le joueur ajoute 1 car les indices commencent à zéro.

La branche de liste vide affiche un message et évite de chercher une question inexistante. Les données de cette révision restent inchangées pendant sa consultation.

L’état du pager, notamment sa position. Il est distinct de l’état de la partie.

💡

pageCount

« Nombre de pages ». Ici, il dépend du nombre de questions, pas d’une valeur fixée à quatre.

currentPage

04 / Le geste et les boutons commandent la même vue

Une coroutine accompagne le déplacement.

Les boutons utilisent animateScrollToPage pour demander au pager un déplacement animé. Cet appel suspendable est lancé dans une coroutine liée à la vue par rememberCoroutineScope.

Tu retrouves l’idée de la partie asynchrone : le déplacement se déroule dans le temps sans bloquer le fil d’interface. Le presenter ne calcule rien pour cette animation.

  • À la première fiche, « Précédente » est désactivé.
  • À la dernière, « Suivante » est désactivé.
  • Pendant un déplacement, les deux boutons attendent sa fin.
  • Le bouton « Retour au résultat » conserve son rôle : quitter la révision sans recommencer.

Dans enabled, && signifie « et » : il faut être dans les bornes de la liste et ne pas être en cours de déplacement. La valeur lastIndex désigne l’indice du dernier élément.

Pourquoi les pages ne sont-elles pas les questions du quiz en cours ?

La révision montre déjà les solutions et permet de revenir en arrière. La partie conserve ses règles de première réponse et de comptage. Mélanger ces états imposerait de nouvelles décisions sur les réponses sautées ou revues ; ce n’est pas l’objectif de cette extension.

Et si je ferme la révision pendant le déplacement ?

La coroutine liée à cette vue est annulée quand elle quitte la composition. Ce n’est pas une sauvegarde de la position. Dans la version de cet exercice, ne promets pas de retrouver la dernière fiche après fermeture et réouverture.

💡

animateScrollToPage

« Faire défiler avec animation vers une page ». L’argument est l’indice de destination.

💡

CoroutineScope

Le cadre de vie des coroutines lancées. Ici, il est associé à la vue de révision.

💡

Bornes de la liste

Les indices utilisables : de zéro au dernier indice lorsqu’il existe des éléments.

05 / Une page doit rester lisible

Sépare le balayage horizontal de la lecture verticale.

Le pager reçoit la hauteur restante sous le titre, le retour et le repère. Dans chaque page, une Column défilante permet de lire une fiche plus longue que cette zone.

Le déplacement horizontal change de fiche ; le déplacement vertical permet de lire la fiche actuelle. Ce sont deux directions différentes, avec une hauteur bornée dans cet exemple. N’ajoute pas un parent défilant horizontal autour du pager.

Garde les textes entiers et vérifie les boutons sur un petit écran et avec une police plus grande. Si la présentation devient encombrée, une liste verticale peut mieux répondre à ton besoin.

Peut-on utiliser VerticalPager ?

Oui, pour changer de page verticalement. Ce n’est pas juste un remplacement de nom à faire ici : il faudrait aussi réfléchir au geste de lecture d’un texte long qui défile déjà verticalement. On garde une seule variante pour comprendre le besoin avant d’étendre.

💡

Zone de lecture

La place disponible pour consulter la fiche. Elle doit permettre d’accéder à l’ensemble du contenu, même lorsqu’il est long.

06 / Prévoir, parcourir et comparer

La révision avance, le score reste identique.

  1. Termine une partie et note son score. Ouvre la révision : vérifie le premier numéro et la première question.
  2. Avance par balayage, puis avec le bouton. Le repère doit correspondre à la fiche consultée après le déplacement.
  3. Reviens à la première fiche, puis atteins la dernière. Vérifie les boutons désactivés aux extrémités et l’absence de page supplémentaire.
  4. Lis un énoncé long en faisant défiler son contenu verticalement.
  5. Retourne au résultat : le score doit être identique. Vérifie aussi une nouvelle partie avec « Recommencer ».
  6. Avec l’encadrant, essaie une seule question puis une liste vide dans les données du clone. Le total attendu change : vérifie une fiche unique sans déplacement, puis le message de révision vide. Restaure ensuite tes données.
