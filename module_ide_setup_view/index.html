Ton premier lancement

Ouvrir et lancer ton quiz.

Ton projet est sur ton ordinateur. Maintenant, ouvre-le dans Android Studio, retrouve ses fichiers et fais apparaître son écran d’accueil sur un appareil Android.

Objectif : comprendre le trajet du dossier jusqu’à l’application. Tu observes le projet existant, sans modifier son code.

Avec l’encadrant, avant de commencer

Préparez Android Studio et un téléphone ou un émulateur déjà utilisable. Prévoyez une connexion Internet pour la première préparation du projet.

Repères techniques pour l’encadrant
  • Projet Android cloné à la page Git précédente, branche dev.
  • SDK Android : ensemble des outils et fichiers nécessaires pour construire l’application. Ce projet utilise la plateforme Android 36.
  • JDK : outils Java utilisés par Gradle. Vérifier sa compatibilité avec le projet ; le code cible Java 17.
  • Installer les composants manquants et accepter les licences avec l’élève, en expliquant la demande affichée.
  • Appareil Android 8.0 (API 26) ou plus récent. API désigne ici le niveau de version technique d’Android. Pour un téléphone physique, préparer sa connexion et l’autorisation de débogage ; pour un émulateur, préparer l’appareil virtuel.

Ces réglages servent à préparer l’atelier. L’élève n’a pas à les mémoriser pour poursuivre.

01 / Le bon dossier

Ouvre le projet que tu as cloné.

  1. Lance Android Studio. Sur l’écran d’accueil, choisis Open (ouvrir). Si un autre projet est déjà ouvert, utilise File → Open… (fichier → ouvrir).
  2. Retrouve ton dossier stage_academy, à l’endroit choisi pendant le clone.
  3. Sélectionne le dossier qui contient settings.gradle.kts et le sous-dossier app, puis ouvre-le.
stage_academy/          ← dossier à ouvrir
  settings.gradle.kts
  README.md
  app/
    build.gradle.kts
    src/

Tu reprends un projet existant : le bouton New Project (nouveau projet) sert à en créer un autre. Ici, tu n’en as pas besoin.

Android Studio demande si je fais confiance au projet

Lis la demande avec ton encadrant et vérifie que tu as bien ouvert le clone du dépôt prévu. Ouvrir un projet peut lancer ses outils de construction ; demande-lui de t’aider à choisir.

💡

Racine · root

Le dossier principal du projet. Ici, c’est stage_academy, qui contient notamment app. On ouvre l’ensemble pour que l’IDE connaisse son organisation.

02 / Laisser l’atelier se préparer

L’IDE découvre comment construire l’app.

Android Studio lit les réglages du projet et lance une synchronisation avec Gradle. Certains outils ou dépendances peuvent être téléchargés. La première fois, cela peut prendre plusieurs minutes.

Observe la progression et les messages. Attends la fin de la synchronisation avant de lancer l’application. Les intitulés et la position des panneaux peuvent varier selon la version d’Android Studio.

Synchroniser ne lance pas le quiz.

Cette étape permet à l’IDE de comprendre le projet et ses besoins. Le lancement sur l’appareil vient ensuite.

La préparation échoue ou semble bloquée

Ouvre les messages de synchronisation ou le panneau Build (construction). Repère le premier message d’erreur utile et montre-le à l’encadrant. Ensemble, vérifiez la connexion, les composants demandés et les réglages indiqués. Garde le message visible pour comprendre ce qui bloque.

💡

Synchronisation · sync

Ici, mettre à jour ce que l’IDE connaît des réglages du projet. Ce n’est pas un envoi sur GitHub.

💡

Gradle

L’outil qui organise les tâches nécessaires à la construction de l’application, à partir des réglages du projet.

💡

Dépendance · dependency

Un morceau de logiciel réutilisé par le projet. Par exemple, Compose fournit des outils pour décrire les écrans.

03 / Reconnaître les rôles

Cinq repères, sans tout lire.

Dans le panneau Project (projet), sélectionne la vue Project si tu veux retrouver les dossiers comme sur ton ordinateur. La vue Android les regroupe autrement : les fichiers restent les mêmes.

Déplie les dossiers et ouvre les fichiers ci-dessous. Pour chacun, dis à ton encadrant à quoi il sert. Tu n’as pas besoin de comprendre toutes ses lignes.

README.md

Le point de départ écrit pour les personnes : présentation et consignes du projet. Un fichier .md contient du texte avec une mise en forme légère appelée Markdown.

Le dossier app/

Le module qui regroupe le code, les ressources et les réglages de notre application Android.

MainActivity.kt

app/src/main/java/fr/stageacademy/quiz/MainActivity.kt

Le point d’entrée de notre écran : ce fichier Kotlin installe l’interface décrite avec Compose. Le dossier s’appelle java, mais il contient bien ici du Kotlin.

strings.xml

app/src/main/res/values/strings.xml

Les textes réutilisés par l’application. Retrouve welcome_title et le texte « Mon premier quiz ».

app/build.gradle.kts

Les réglages de construction du module : versions Android et dépendances, par exemple. Ce fichier configure les outils ; il ne dessine pas l’écran.

Petit défi : où chercher pour changer le titre de bienvenue ?

Dans app/src/main/res/values/strings.xml, à l’entrée welcome_title. Aujourd’hui, repère-la seulement. On modifiera le texte dans une prochaine étape.

💡

Module

Une partie du projet qui rassemble des fichiers et des réglages de construction. Notre projet a un module Android nommé app.

💡

Kotlin · .kt / .kts

Le langage utilisé pour programmer notre quiz. Les fichiers .kt contiennent son code ; .kts désigne un script Kotlin, utilisé ici pour les réglages Gradle.

💡

Compose

Les outils Android avec lesquels on décrit l’interface en Kotlin : textes, boutons et disposition à l’écran.

💡

Ressource / XML

Une ressource est un élément utilisé par l’app, comme un texte ou une image. XML est un format qui organise des informations avec des balises. Ici, strings.xml contient des textes nommés.

04 / Du projet à l’écran

Lance l’application existante.

  1. Dans la barre d’outils, sélectionne la configuration de lancement app.
  2. Choisis le téléphone ou l’émulateur préparé avec l’encadrant dans la liste des appareils.
  3. Clique sur le triangle Run ▶ (exécuter). Android Studio construit l’application, l’installe sur cet appareil et la lance.
  4. Observe les messages de construction, puis l’écran de l’appareil. Le premier lancement peut prendre du temps.

Résultat attendu sur l’appareil

Mon premier quiz

Bienvenue ! Ici, nous allons construire notre quiz pas à pas.

Ces textes viennent du projet de départ. Ce cadre est un repère de lecture, pas un appareil connecté ni une preuve que ton lancement a réussi.

Le quiz ne propose pas encore de questions : tu viens de lancer son écran de départ. Compare les textes affichés avec ceux de strings.xml.

Aucun appareil n’apparaît, ou l’application ne s’ouvre pas

Demande à l’encadrant de vérifier l’appareil préparé et sa connexion. Si la construction échoue, lis le panneau Build. Si elle réussit mais que l’écran attendu n’apparaît pas, vérifiez l’appareil sélectionné et le message de lancement. Distingue ces deux situations avant de réessayer.

💡

Configuration de lancement

Les indications utilisées par l’IDE pour lancer une partie du projet. Ici, on choisit app.

💡

Appareil cible · target device

Le téléphone ou l’émulateur sur lequel tu demandes à l’IDE d’exécuter l’application.

💡

Émulateur · emulator

Un appareil Android virtuel qui fonctionne sur ton ordinateur. Le quiz y tourne comme sur un appareil de test.

05 / À toi de montrer

Du dossier au résultat, tu sais te repérer.

Avec ton encadrant, coche ce que tu as réellement fait. Les cases sont des confirmations personnelles : le guide ne vérifie pas Android Studio et ne sauvegarde pas ta progression.

Mes repères dans le vrai projet
Question : synchroniser suffit-il à voir le quiz sur le téléphone ?

Non. La synchronisation prépare la compréhension du projet dans l’IDE. Il faut ensuite sélectionner une configuration, un appareil et lancer l’application avec Run.

Prochaine étape : comprendre une petite modification du code et observer son effet à l’écran. Pour aujourd’hui, explique à ton encadrant le trajet que tu viens de suivre.
