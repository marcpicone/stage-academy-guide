Une place pour chaque rôle

Séparer la vue et les règles du quiz.

Tes questions ont un modèle et un affichage commun. Donne maintenant un rôle précis à une classe : vérifier les réponses, sans connaître les boutons ou les messages à l’écran.

Objectif : déplacer une règle déjà comprise, puis suivre son appel depuis le clic. Nous gardons les mêmes questions et les mêmes résultats.

01 / Reconnaître les responsabilités

Qui doit savoir quoi ?

Jusqu’ici, MainActivity.kt contient les données, la validation et les vues. Cherche ce qui changerait pour modifier la bonne réponse, changer un libellé ou modifier la règle de validation : ces besoins ne concernent pas les mêmes éléments.

Question · les données
Connaît l’énoncé, les choix et la bonne réponse.
QuizPresenter · la règle
Reçoit une question et un choix, puis indique si ce choix est correct.
QuestionView · l’affichage
Affiche les données, transmet les clics et traduit le résultat en message.

Dans cette étape, le message et son état Compose restent dans la vue. Le presenter ne gère pas encore le score ou le passage à la question suivante. Nous lui donnons une première responsabilité simple et vérifiable.

Avec l’encadrant, garde d’abord le quiz fonctionnel dans Git, puis prépare une branche comme ab/separer_validation_et_vue.

💡

Responsabilité · responsibility

Le travail précis confié à une partie du programme. Comprendre qui fait quoi aide à savoir où intervenir.

💡

Presenter

Le nom choisi ici pour une classe qui portera les règles et, plus tard, le déroulement du quiz. Ce n’est pas un mot-clé Kotlin ni une fonction spéciale d’Android.

02 / Une classe qui porte une action

Déclare QuizPresenter.

Question était une data class pour décrire des informations. Nous utilisons maintenant une classe Kotlin ordinaire pour regrouper une action :

class QuizPresenter {
    fun isCorrectAnswer(
        question: Question,
        selectedAnswer: String,
    ): Boolean {
        val result: Boolean = selectedAnswer == question.correctAnswer
        return result
    }
}

Tu reconnais la comparaison de la page sur les fonctions. Elle est maintenant placée dans les accolades de la classe QuizPresenter. Une fonction qui appartient à une classe est aussi appelée une méthode.

L’action reçoit une Question et le texte choisi. Elle lit question.correctAnswer et renvoie un Boolean. Elle n’affiche rien et ne contient aucun outil Compose.

Nous n’avons pas changé la règle : l’égalité exacte des textes reste le critère. Recevoir la question complète rend explicite l’information utilisée par le presenter.

💡

Méthode · method

Une fonction qui appartient à une classe. Ici, isCorrectAnswer appartient à QuizPresenter.

💡

Classe ordinaire / data class

Les deux définissent des types. Question utilise data pour représenter des données ; QuizPresenter est une classe à laquelle nous confions une action.

03 / Créer, transmettre, appeler

Une instance concrète du presenter.

Comme pour une question, on crée une instance de la classe :

val presenter: QuizPresenter = QuizPresenter()

QuizPresenter est le type et le modèle. presenter est le nom de la variable qui désigne l’objet créé par QuizPresenter(). Cet objet possède la méthode de validation.

Depuis la vue, on lui demande le travail avec le point :

val isAnswerCorrect: Boolean = presenter.isCorrectAnswer(
    question = question,
    selectedAnswer = selectedAnswer,
)

La vue connaît cet objet parce qu’on le lui transmet comme paramètre. Elle ne le retrouve pas toute seule et il n’est pas créé par un mécanisme Android caché.

  1. Le joueur clique sur un choix.
  2. La vue appelle presenter.isCorrectAnswer avec la question et le choix.
  3. Le presenter renvoie true ou false.
  4. La vue utilise ce résultat pour mettre à jour son message.

Le if qui choisit « Bonne réponse ! » ou « Essaie encore. » reste dans la vue : il choisit la présentation d’un résultat. La règle qui décide si la réponse est correcte est dans le presenter.

💡

Instance · instance

L’objet concret créé à partir d’une classe. Ici, une même instance de QuizPresenter sera transmise aux vues des différentes questions.

💡

Transmettre · pass

Fournir un objet ou une valeur comme argument d’un appel. Les paramètres rendent les liens visibles dans le code.

Dans l’IDE, tu peux créer un fichier Kotlin depuis le menu contextuel du dossier avec New → Kotlin Class/File (nouveau → classe/fichier Kotlin). Le libellé peut varier. Choisis un fichier si tu veux y placer le contenu complet fourni.

Le même package permet ici d’utiliser ces types sans ajouter d’import entre eux. Mettre une classe dans un autre fichier aide à la retrouver ; ce rangement ne crée pas à lui seul une protection ou une nouvelle règle métier.

💡

Package

Le groupe logique auquel appartient le code Kotlin. La ligne package en haut du fichier indique ce groupe. Nous gardons le même package que le projet de départ.

Déplacer / dupliquer

05 / Brancher la vue sur son presenter

Rendre chaque lien visible.

Dans WelcomeScreen, ajoute la création conservée du presenter avant les questions :

val presenter: QuizPresenter = remember { QuizPresenter() }

remember, déjà rencontré pour l’état d’écran, conserve ici la même instance pendant les mises à jour de cette vue. Ce n’est ni une sauvegarde durable ni une création automatique : l’appel QuizPresenter() est écrit à cet endroit. Comme le presenter ne garde encore aucun état, cela prépare surtout un emplacement clair pour son instance.

Dans la boucle, transmets-le à chaque vue :

for (question: Question in questions) {
    QuestionView(question = question, presenter = presenter)
}

QuestionView reçoit maintenant deux paramètres. Remplace sa définition par :

@Composable
fun QuestionView(
    question: Question,
    presenter: QuizPresenter,
) {
    var feedbackText: String by remember(question) {
        mutableStateOf("Choisis une réponse.")
    }

    fun checkAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = presenter.isCorrectAnswer(
            question = question,
            selectedAnswer = selectedAnswer,
        )
        if (isAnswerCorrect) {
            feedbackText = "Bonne réponse !"
        } else {
            feedbackText = "Essaie encore."
        }
    }

    Column(
        verticalArrangement = Arrangement.spacedBy(12.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(text = question.text)
        for (choice: String in question.choices) {
            Button(onClick = { checkAnswer(choice) }) {
                Text(text = choice)
            }
        }
        Text(text = feedbackText)
    }
}
Comparer le WelcomeScreen complet

Ce cadre montre les deux questions initiales pour rester court. Si tu en as déjà quatre, garde leurs instances et la liste qui les contient. Les changements concernent uniquement la création et la transmission du presenter.

@Composable
fun WelcomeScreen(modifier: Modifier = Modifier) {
    val presenter: QuizPresenter = remember { QuizPresenter() }

    val firstQuestion: Question = Question(
        text = "Quel outil garde l’historique du code ?",
        choices = listOf("Git", "Android", "Compose"),
        correctAnswer = "Git",
    )

    val secondQuestion: Question = Question(
        text = "Quel composant Compose affiche du texte ?",
        choices = listOf("Button", "Text", "Column"),
        correctAnswer = "Text",
    )

    val questions: List<Question> = listOf(firstQuestion, secondQuestion)

    Column(
        modifier = modifier
            .fillMaxSize()
            .verticalScroll(rememberScrollState())
            .padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(24.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(
            text = stringResource(R.string.welcome_title),
            style = MaterialTheme.typography.headlineMedium,
        )
        for (question: Question in questions) {
            QuestionView(question = question, presenter = presenter)
        }
    }
}

Une fois tous les appels mis à jour, retire l’ancienne fonction isCorrectAnswer déclarée seule au niveau du fichier dans MainActivity.kt. La méthode du presenter doit être l’unique emplacement de cette règle. Garde la classe MainActivity, sa prévisualisation et les imports Compose existants.

L’IDE signale un nom inconnu ou un paramètre manquant

Vérifie le package de Question.kt et QuizPresenter.kt. Dans MainActivity.kt, cherche tous les appels de QuestionView : chacun doit fournir presenter. Dans l’action du clic, l’appel doit commencer par presenter.isCorrectAnswer. Un oubli à l’un de ces endroits peut empêcher la compilation.

💡

Dépendance explicite

QuestionView a besoin d’un QuizPresenter pour valider. Son paramètre le montre et son appelant doit le fournir.

💡

État de la vue

Le message reste stocké dans QuestionView. Le presenter de cette page n’a aucun état à modifier : il renvoie seulement le résultat de la vérification.

Lire la correction

Question.kt pour la forme des données, QuizPresenter.kt pour la règle et MainActivity.kt, dans QuestionView, pour les messages affichés. Les questions concrètes restent créées dans WelcomeScreen à cette étape.

Pourquoi ne pas faire appeler Text ou Button par le presenter ?

Sa tâche est de décider si une réponse est correcte. En restant indépendant de Compose, cette règle peut être vérifiée sans dessiner un écran. La vue utilise le résultat pour choisir ce qu’elle affiche.
