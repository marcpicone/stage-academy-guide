Python : fabriquer tes outils.

Utilise une bibliothèque pour préparer une image du quiz. Avec un petit script Python et uv, crée une copie plus petite que tu pourras retrouver et comparer à l’original.

Tu connais déjà les variables, fonctions et conditions, ainsi que le terminal. Cette page les retrouve dans un autre langage avec un objectif concret : produire une image PNG réduite, sans changer l’original.

01 / Programmer aussi ce qui t’aide à travailler

Préparer une image sans répéter les mêmes manipulations.

Tu récupères une illustration pour ton quiz. Elle est grande, et tu veux une copie plus petite. Tu peux le faire dans un logiciel d’image ; tu peux aussi écrire une fois les étapes et demander à l’ordinateur de les refaire pour une autre source.

Un script est ici un fichier de code qu’on lance pour réaliser cette tâche. Python est le langage utilisé. Il peut servir à de nombreux types de programmes ; nous l’utilisons maintenant pour un outil de préparation de fichiers.

  1. Une entrée

    Le chemin de l’image que tu veux préparer.

  2. Une action

    Réduire ses dimensions en conservant ses proportions.

  3. Une sortie

    Un nouveau fichier PNG et un message indiquant où le retrouver.

Le script travaille sur des fichiers dans ton ordinateur, avant leur éventuelle utilisation dans l’application. Ce n’est pas un effet de taille appliqué à un composant Compose pendant l’affichage.

💡

Tooling · outillage

Les outils qui facilitent le travail : préparer des fichiers, vérifier des données ou enchaîner des opérations.

💡

Automatiser · automate

Décrire une tâche pour qu’un programme puisse l’exécuter à nouveau, selon les informations qu’on lui donne.

02 / Profiter du travail déjà disponible

Tu n’as pas à écrire le traitement d’image toi-même.

Python possède une bibliothèque standard, fournie avec le langage, et un très grand écosystème de bibliothèques supplémentaires. PyPI est un catalogue de paquets Python où beaucoup d’entre elles sont distribuées.

Fichiers et dossiers

La bibliothèque standard fournit notamment pathlib pour représenter les chemins, ainsi que des outils pour copier des fichiers et préparer des archives.

Images

Pillow peut ouvrir une image, en modifier les dimensions et enregistrer un résultat. C’est la bibliothèque supplémentaire choisie pour cet exercice.

Données, réseau et autres besoins

D’autres bibliothèques aident à manipuler des tableaux, produire des documents ou communiquer avec des services. On choisit selon la tâche et sa documentation, plutôt que d’installer tout un catalogue.

Tu retrouves l’idée des dépendances Gradle : ton code utilise une bibliothèque existante. Ici, pillow est le nom du paquet à déclarer, et PIL est le nom utilisé par ses imports Python :

from PIL import Image

Cette ligne rend les possibilités d’Image accessibles dans le script. Il faut aussi que Pillow soit disponible dans son environnement d’exécution : c’est là qu’uv nous aide.

💡

Bibliothèque · library

Du code réutilisable qui fournit des possibilités à ton programme. Dans les échanges, tu verras aussi l’abréviation « lib ».

💡

Paquet · package

Une forme de distribution du code Python à installer. Ici, le paquet Pillow contient les outils de traitement d’image que nous importons.

03 / Préparer ce dont le script a besoin

uv lance le script avec ses dépendances.

Copier un fichier Python sur une autre machine ne suffit pas toujours : il faut une version compatible de Python et les bibliothèques utilisées. uv est un outil qui peut préparer cet environnement et lancer le script.

Python

Le langage et l’interpréteur qui exécutent le code.

Pillow

La bibliothèque qui réalise le traitement de l’image.

uv

L’outil qui prépare l’environnement et lance notre fichier.

Notre script déclare ses besoins dans un petit en-tête. uv le lit, choisit un Python compatible et prépare un environnement isolé avec Pillow. Il réutilise des éléments déjà disponibles ; un premier lancement peut télécharger Python ou des dépendances et demander une connexion.

Cela facilite le partage du script et évite de préparer manuellement son environnement à chaque fois. uv ne transforme pas ce fichier en application autonome et ne garantit pas que tous les outils externes soient installés. ImageMagick, par exemple, est un autre outil ; il n’est pas nécessaire à cet exercice Pillow.

Avec l’encadrant, prépare uv en suivant sa documentation d’installation adaptée à Windows, macOS ou Linux. Dans un terminal normal, vérifie :

uv --version

Un numéro doit apparaître. Si la commande n’est pas reconnue, fais vérifier l’installation et rouvre le terminal si nécessaire. Le guide reste consultable hors ligne, mais cette préparation de l’environnement peut utiliser le réseau.

Comment uv connaît-il Pillow ?

Les lignes entre # /// script et # /// déclarent la version Python acceptée et la dépendance Pillow. Ce sont des métadonnées : des informations pour l’outil, placées dans des commentaires Python.

La plage de versions déclarée n’impose pas une version unique de Pillow. uv permet aussi de verrouiller les dépendances dans un fichier associé ; on pourra approfondir ce besoin lorsque l’outil devra être conservé et partagé durablement.

💡

Interpréteur · interpreter

Le programme qui exécute le code Python. Le fichier .py est ton code ; l’interpréteur est l’outil qui le fait fonctionner.

💡

Environnement isolé

Un espace de dépendances préparé pour ce script, afin de ne pas supposer que les mêmes bibliothèques sont déjà installées partout.

04 / Un premier outil fourni et expliqué

Prépare resize_image.py et une image source.

Crée un petit dossier de travail quiz_image_tool, distinct des projets Android et Desktop. Ouvre-le dans ton IDE ou ton éditeur. Pour cette première manipulation, choisis une illustration PNG que tu peux utiliser, idéalement carrée et d’au moins 512 × 512 pixels.

quiz_image_tool/
├── resize_image.py
└── source.png

Télécharger le script resize_image.py, ou copie son contenu ci-dessous dans un fichier portant exactement ce nom. Place ton image à côté sous le nom source.png ; choisis une vraie image PNG, pas un autre format simplement renommé.

Le script complet fourni
# /// script
# requires-python = ">=3.11"
# dependencies = ["pillow>=11,<14"]
# ///

import argparse
from pathlib import Path

from PIL import Image


def resize_image(source_path: Path, output_path: Path, max_size: int) -> None:
    with Image.open(source_path) as source_image:
        original_width: int = source_image.width
        original_height: int = source_image.height
        result_image: Image.Image = source_image.convert("RGBA")
        result_image.thumbnail((max_size, max_size), Image.Resampling.LANCZOS)
        output_path.parent.mkdir(parents=True, exist_ok=True)
        result_image.save(output_path, format="PNG")

    print(f"Source : {original_width} x {original_height} px")
    print(f"Résultat : {result_image.width} x {result_image.height} px")
    print(f"Image créée : {output_path.resolve()}")


def main() -> None:
    parser = argparse.ArgumentParser(
        description="Créer une copie PNG réduite, sans déformer l’image."
    )
    parser.add_argument("source", type=Path, help="Chemin de l’image source")
    parser.add_argument("output", type=Path, help="Chemin du nouveau fichier PNG")
    parser.add_argument("--max-size", type=int, default=256, help="Côté maximal en pixels")
    args = parser.parse_args()

    if args.max_size <= 0:
        parser.error("La taille maximale doit être supérieure à zéro.")
    if args.output.suffix.lower() != ".png":
        parser.error("Le fichier de sortie doit avoir l’extension .png.")
    if args.source.resolve() == args.output.resolve():
        parser.error("La source et la sortie doivent être des fichiers différents.")
    if args.output.exists():
        parser.error("La sortie existe déjà. Choisis un nouveau nom pour la conserver.")

    try:
        resize_image(args.source, args.output, args.max_size)
    except OSError as error:
        parser.exit(1, f"Impossible de préparer l’image : {error}\n")


if __name__ == "__main__":
    main()

Lis d’abord ces trois appels dans resize_image : Image.open ouvre la source, thumbnail réduit l’image et save écrit le résultat. Pillow effectue le traitement ; notre code organise les chemins, la taille et les messages.

Des notions connues, avec une autre syntaxe
Dans le scriptCe que tu reconnais
def resize_image(...) -> None:Une fonction, ses paramètres et aucun résultat utile retourné à l’appelant. Son travail est de créer un fichier et d’afficher des messages.
max_size: intUn paramètre entier. Les annotations aident à lire les types ; Python ne les impose pas comme le compilateur Kotlin.
if args.max_size <= 0:Une condition pour refuser une taille qui n’a pas de sens.
Les lignes décalées sous def, if ou withDes blocs de code. En Python, l’indentation délimite ces blocs ; il faut conserver les espaces du script.

Les noms restent en anglais. Python emploie couramment le snake_case : source_path signifie « chemin source » et max_size « taille maximale ». Les mots d’un nom sont séparés par des underscores.

Que font les autres lignes fournies ?

argparse, fourni avec Python, lit les informations de la commande. Path représente un chemin. with aide à fermer le fichier ouvert après le travail. try/except permet d’afficher un message si une opération de fichier échoue.

La fonction main prépare les arguments et lance l’action. Les deux dernières lignes la déclenchent quand ce fichier est exécuté comme script. Tu peux utiliser ce cadre fourni et approfondir chaque partie quand tu en as besoin.

💡

Pixel · px

Un point de l’image. 512 × 512 signifie ici 512 pixels de large et 512 pixels de haut ; cette page travaille sur ces dimensions du fichier.

💡

Proportions

Le rapport entre largeur et hauteur. On le conserve pour éviter de transformer un cercle en ovale.

💡

Indentation

Les espaces au début des lignes. Dans ce code, quatre espaces marquent un niveau de bloc.

05 / Une commande, une nouvelle image

Lance le script depuis son dossier.

Ouvre le terminal dans quiz_image_tool, à côté du script et de source.png. Si tu es encore dans Codex, quitte sa conversation avec /quit ou utilise un autre terminal : la commande ci-dessous doit être exécutée par le terminal.

uv run resize_image.py "source.png" "output/quiz_small.png" --max-size 256

Cette même forme convient dans PowerShell et dans un terminal macOS/Linux après préparation d’uv. uv run lance le fichier ; les deux chemins sont la source et la sortie ; --max-size 256 fixe la limite de largeur et de hauteur.

Le script crée le dossier output s’il manque. Il garde l’original et refuse d’écraser un fichier de sortie existant. Pour refaire un essai, donne un nouveau nom au résultat.

Avec une source carrée de 512 × 512 px : une sortie de 256 × 256 px.

Le terminal indique les dimensions source et résultat, ainsi que le chemin du fichier créé. Ouvre ce fichier pour observer l’image ; un message seul ne remplace pas cette vérification.

256 × 256 est une limite, pas une demande de carré déformé. Une image de 800 × 400 px devient 256 × 128 px. Une image déjà plus petite, comme 128 × 128 px, reste à cette taille : ce script n’agrandit pas la source.

La réduction du nombre de pixels ne garantit pas une taille de fichier toujours plus faible : le format, la transparence et la compression interviennent aussi. Ici, on vérifie d’abord les dimensions et les proportions.

Comment afficher l’aide du script ?
uv run resize_image.py --help

Tu retrouves les chemins attendus et l’option de taille. Les noms source, output et max-size sont les paramètres de notre outil, pas de nouvelles commandes uv.

Le lancement échoue

Lis le message et le dossier courant. Vérifie le nom du script, la présence de source.png et les guillemets autour des chemins avec espaces. Si la sortie existe déjà, change son nom ; si la source est absente ou illisible, retrouve une vraie image valide.

Si uv ne peut pas préparer Python ou Pillow, examine avec l’encadrant le téléchargement ou la compatibilité signalée. Un ModuleNotFoundError sur PIL peut aussi venir d’un lancement avec un autre environnement que celui préparé par uv : reprends la commande complète et conserve l’en-tête du script.

💡

Argument de commande

Une information transmise au script lors du lancement. Ici, les chemins et la taille jouent ce rôle.

💡

thumbnail · miniature

L’opération Pillow choisie pour réduire une image dans des dimensions maximales, en conservant ses proportions.

06 / Comprendre ton outil en le manipulant

Change un paramètre et prévois le résultat.

  1. Vérifie les dimensions de la source et annonce celles attendues. Lance la commande à 256, puis ouvre le résultat et compare-le à l’original.
  2. Relance avec --max-size 128 et une sortie différente, par exemple output/quiz_smaller.png. Prévois ce qui changera.
  3. Avec une seconde image rectangulaire, vérifie que le script garde ses proportions. Avec une petite image, vérifie qu’il ne l’agrandit pas.
  4. Essaie une taille nulle ou le même nom de sortie déjà créé. Lis le refus et vérifie que les fichiers existants sont conservés.
  5. Montre l’en-tête qui déclare Pillow, la fonction qui traite l’image et la commande qui fournit ses informations.
Utiliser l’agent pour comprendre, puis améliorer

Depuis le dossier de l’outil, tu peux demander :

Lis resize_image.py sans le modifier.
Explique les rôles de Python, uv, argparse, pathlib et Pillow.
Montre comment les arguments de la commande arrivent dans resize_image.
Explique pourquoi une source 800 x 400 devient 256 x 128 avec la limite 256.
Indique ce qui protège l’original et une sortie déjà présente.

Retrouve ensuite les lignes citées. Pour une amélioration, décris d’abord le besoin et les résultats attendus ; le traitement de plusieurs fichiers pourra venir après ce premier outil à une image.

Pour partager ton outil, conserve le script avec son en-tête et sa commande d’exemple. L’autre personne aura besoin d’uv, de l’image d’entrée et des accès nécessaires à la préparation de l’environnement. La configuration dépend des besoins déclarés, pas de ce qui est installé par hasard sur ton ordinateur.
