01 / Quand la collection grandit

Une page pour relire les questions après la partie.

Ton quiz montre une question à la fois. Ajoutons un autre usage : à la fin, le joueur peut ouvrir une page de révision avec les énoncés et leurs bonnes réponses.

Cette page consulte les données sans valider de choix ni modifier le score. Elle devient accessible après la fin de partie, pour ne pas montrer les solutions pendant le quiz.

Avec quelques éléments, une Column suffit souvent. Mais si la collection grandit, construire tous ses éléments d’un coup peut devenir inutilement coûteux. Une liste lazy prépare les éléments selon les besoins de la zone affichée ; cela ne signifie pas que les données sont téléchargées progressivement.

List décrit les données ; LazyColumn décrit leur affichage.

Tu gardes ta liste de questions. Tu choisis maintenant comment présenter ses éléments et permettre leur défilement.

Le fonctionnement des listes lazy est détaillé dans la documentation Android. Avec quatre questions, l’objectif est de comprendre le composant, pas de prétendre mesurer un gain de performance.

💡

Lazy · à la demande

Le composant prépare le contenu de la liste selon les besoins d’affichage. Lazy ne signifie pas « un programme volontairement lent ».

💡

Révision · review

Ici, relire les questions et les solutions après la partie. Ce n’est pas la revue des changements Git.

02 / Choisir selon le contenu

Une colonne ou une ligne, avec ou sans liste lazy.

Quel composant pour quel besoin ?
ComposantBesoinExemple dans le quiz
ColumnPetit groupe vertical ; défilement à ajouter si nécessaire.Titre, phrase et bouton d’accueil.
RowPetit groupe horizontal.Numéro de question et score.
LazyColumnCollection défilante verticale.Réviser beaucoup de questions.
LazyRowCollection défilante horizontale.Parcourir des cartes courtes côte à côte.

Une carte de révision est un bloc qui regroupe l’énoncé et la bonne réponse. Lis d’abord une question longue : une liste verticale peut être plus confortable qu’une rangée de cartes étroites.

La même collection peut donc avoir deux présentations. Il n’est pas nécessaire de garder les deux dans la version finale : compare-les puis choisis celle qui répond au besoin.

💡

Défilement · scrolling

Le déplacement du contenu pour atteindre les éléments qui ne tiennent pas dans la zone visible.

💡

Carte · card

Un bloc visuel qui regroupe des informations liées. Ici, une question et sa solution.

03 / Décrire les éléments à afficher

Une carte par question avec items.

Dans la version du cours, Question possède déjà text et correctAnswer. Ajoute les imports manquants et les deux fonctions ci-dessous dans le fichier des vues, à l’extérieur des autres fonctions. Garde les imports Compose existants.

Si ton code a été réorganisé par un agent, repère le modèle et les vues équivalentes avec l’encadrant ; ne remplace pas ton application entière.

import androidx.compose.foundation.layout.fillMaxWidth
import androidx.compose.foundation.layout.width
import androidx.compose.foundation.lazy.LazyColumn
import androidx.compose.foundation.lazy.LazyRow
import androidx.compose.foundation.lazy.items
import androidx.compose.material3.Card
@Composable
private fun ReviewCard(
    question: Question,
    modifier: Modifier = Modifier,
) {
    Card(modifier = modifier.fillMaxWidth()) {
        Column(
            modifier = Modifier.padding(16.dp),
            verticalArrangement = Arrangement.spacedBy(8.dp),
        ) {
            Text(text = question.text)
            Text(text = "Bonne réponse : ${question.correctAnswer}")
        }
    }
}

@Composable
private fun ReviewScreen(
    questions: List<Question>,
    onBack: () -> Unit,
    modifier: Modifier = Modifier,
) {
    Column(
        modifier = modifier.fillMaxSize().padding(16.dp),
        verticalArrangement = Arrangement.spacedBy(16.dp),
    ) {
        Text(text = "Réviser les questions")
        Button(onClick = onBack) {
            Text(text = "Retour au résultat")
        }
        LazyColumn(
            modifier = Modifier.weight(1f).fillMaxWidth(),
            verticalArrangement = Arrangement.spacedBy(16.dp),
        ) {
            items(questions) { question: Question ->
                ReviewCard(question = question)
            }
        }
    }
}

items(questions) décrit comment afficher chaque élément. Dans son bloc, question est la question utilisée pour cette carte. Ce n’est pas un appel à for qui construit toute la liste de vues à l’avance.

onBack signifie « au retour » : l’écran reçoit une action, sans avoir à connaître le presenter. weight(1f) utilise ici la hauteur restante sous le titre et le bouton. fillMaxWidth() prend la largeur disponible.

Pourquoi ne pas mettre cette LazyColumn dans la Column défilante du quiz ?

On crée un écran séparé pour lui donner une hauteur disponible définie. Une liste verticale dans un parent vertical défilant sans hauteur limitée peut provoquer une erreur de mesure. Ne rajoute pas verticalScroll à la LazyColumn : elle gère déjà son défilement.

💡

items · éléments

Le bloc qui décrit la présentation de chaque donnée de la liste.

💡

Modifier

Les indications de taille, d’espace et de disposition appliquées au composant. Ici, la liste occupe la hauteur restante.

💡

onBack

Le nom anglais de l’action de retour. La fonction de vue la reçoit en paramètre.

04 / Relier la page au parcours

Ouvre la révision depuis le résultat.

Dans WelcomeScreen de la version du cours, ajoute le bloc suivant après les déclarations des questions, du presenter et de l’état affiché, juste avant la Column principale. Il doit être en dehors de cette Column.

var showReview: Boolean by remember { mutableStateOf(false) }
if (showReview) {
    ReviewScreen(
        questions = questions,
        onBack = { showReview = false },
        modifier = modifier,
    )
    return
}

Quand showReview est vrai, on affiche la révision et return termine cette exécution de la fonction : le quiz n’est pas dessiné en dessous. Le presenter et les états déjà déclarés restent conservés pendant cette navigation.

Dans la branche if (isQuizFinished) qui affiche le résultat, ajoute ce bouton à côté du code existant de « Recommencer » :

Button(onClick = { showReview = true }) {
    Text(text = "Réviser les questions")
}

Le bouton de retour remet seulement showReview à faux. Il retrouve le résultat sans appeler restart, sans attribuer de point et sans commencer une nouvelle partie.

J’ai déjà un accueil et une navigation différents

Intègre une destination de révision avec l’encadrant ou l’agent en suivant la navigation existante. Demande une ouverture depuis le résultat et un retour vers ce même résultat. N’ajoute pas un second presenter ou une seconde liste de questions : transmets les données déjà présentes.

💡

showReview

« Afficher la révision » : l’état qui choisit ici entre l’écran de révision et le reste de l’écran principal.

💡

Navigation

Le passage d’un écran à un autre. Dans cet exemple simple, un Boolean choisit ce que la fonction affiche.

05 / Comparer avec le même contenu

Essaie une rangée de cartes avec LazyRow.

Pour cette expérience, remplace uniquement le bloc LazyColumn de ReviewScreen par celui-ci. Ne garde pas les deux listes l’une sous l’autre.

LazyRow(
    modifier = Modifier.fillMaxWidth(),
    horizontalArrangement = Arrangement.spacedBy(16.dp),
) {
    items(questions) { question: Question ->
        ReviewCard(
            question = question,
            modifier = Modifier.width(280.dp),
        )
    }
}

Le contenu défile maintenant de gauche à droite. La largeur de 280 dp est un choix d’exemple pour rendre chaque carte identifiable, pas une valeur adaptée automatiquement à tous les appareils.

Compare la lecture de l’énoncé le plus long dans les deux versions. Ajuste si nécessaire et vérifie sur un petit écran. Si les cartes deviennent trop hautes, la version verticale est un choix plus simple pour cet exercice.

Cette rangée permet de faire défiler librement les cartes ; elle ne garantit pas une carte parfaitement centrée à chaque geste. Le passage page par page sera abordé plus tard avec un pager.

💡

dp

Une unité Android utilisée pour dimensionner l’interface en tenant compte de la densité de l’écran.

💡

horizontalArrangement

La disposition et l’espace entre les éléments sur l’axe horizontal.

06 / À toi de comparer

Même donnée, autre présentation, règles conservées.

  1. Termine une partie et note son score. Ouvre la révision : toutes les questions et leurs bonnes réponses doivent être accessibles.
  2. Fais défiler jusqu’à la dernière question. Essaie ensuite la version horizontale et compare la lecture.
  3. Pour rendre le défilement plus visible, ajoute quelques questions de révision ou utilise un appareil plus petit avec l’encadrant. Si tu ajoutes des questions au quiz, son nombre total et ses résultats attendus changent aussi.
  4. Retourne au résultat : le score doit être identique. « Recommencer » doit toujours ouvrir une nouvelle partie à zéro.
  5. Choisis la version la plus lisible et explique pourquoi. Avec une courte liste, ne conclus pas que tu as mesuré un gain de performance.
La liste a des éléments, mais je ne vois pas pourquoi lazy serait utile

Le défilement permet de parcourir le contenu ; la préparation à la demande limite le travail sur les vues d’une grande collection. Ce sont deux aspects différents. Un écran qui défile ne prouve pas à lui seul que la composition est lazy.

Pour plus tard : et si je réordonne des cartes qui ont un état ?

L’identité d’un élément devient importante pour conserver son état. On pourra fournir des clés stables liées aux données. Les cartes de cet exercice sont en lecture seule : nous n’ajoutons pas encore ce sujet ni d’identifiants artificiels.
