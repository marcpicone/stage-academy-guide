Comprendre ce qui travaille derrière Run

Gradle : du code à l’application.

Ton téléphone n’ouvre pas directement les fichiers Kotlin du projet. Découvre comment Gradle organise leur transformation en application, puis produis le fichier APK de ton quiz.

Il suffit d’un clone Android qui se construit déjà avec Android Studio. Les extensions Profil et caméra ne sont pas nécessaires : utilise la version de ton quiz que tu as réellement réalisée.

01 / Préparer ce que l’appareil pourra installer

Gradle organise la construction.

Tu écris du code et tu ajoutes des ressources : textes, icônes, images. La construction, appelée build en anglais, prépare ces éléments et les assemble dans un format utilisable par Android.

Gradle est l’outil qui organise ce travail. Il utilise la configuration du projet et des outils spécialisés, comme le compilateur Kotlin. Le plugin Android lui ajoute les règles et les tâches propres à une application Android.

  1. Les entrées

    Ton code, les ressources, le manifeste et les bibliothèques du projet.

  2. Le travail organisé par Gradle

    Préparer, compiler et assembler les éléments avec les outils nécessaires.

  3. Le résultat de cet exercice

    Un fichier .apk, le paquet d’installation Android de ton quiz.

Schéma simplifié pour comprendre le trajet ; les vraies tâches sont plus nombreuses et certaines peuvent être réutilisées.

Trois actions que tu rencontres dans l’IDE
ActionSon rôle
Sync · synchroniserActualiser la compréhension du projet par l’IDE à partir de la configuration Gradle, notamment après un changement de dépendance. Cela ne lance pas ton quiz.
Build · construireProduire les fichiers demandés à partir du projet. Dans cet exercice, on demande un APK.
Run · lancerPréparer puis installer ou mettre à jour l’app sur l’appareil sélectionné, et la lancer. La construction fait partie de ce parcours.
Pourquoi apprendre une commande si Run fonctionne déjà ?

Pour reconnaître ce que fait l’IDE et pouvoir demander la même construction depuis un terminal, un agent ou une machine d’automatisation. Tu retrouves le même projet et sa configuration.

💡

Compiler · compile

Transformer le code source en une forme que les étapes suivantes pourront utiliser. Compiler fait partie de la construction.

💡

Plugin · extension d’outil

Un composant qui ajoute des possibilités à un outil. Ici, il équipe Gradle pour construire une application Android.

💡

APK

Android Package : le fichier qui rassemble l’application à installer. Il est produit à partir du projet.

02 / Une configuration à plusieurs niveaux

Retrouve le projet et son module app.

Dans le clone Android, affiche les fichiers du projet avec l’encadrant. L’affichage Android de l’IDE peut les regrouper autrement ; l’arbre ci-dessous décrit leurs emplacements réels.

ton-clone-android/
├── settings.gradle.kts
├── build.gradle.kts
├── gradlew
├── gradlew.bat
├── gradle/wrapper/
│   ├── gradle-wrapper.jar
│   └── gradle-wrapper.properties
└── app/
    ├── build.gradle.kts
    └── src/

settings.gradle.kts : quels modules ?

Il décrit notamment les modules inclus dans le projet. Dans le projet de départ, include(":app") déclare le module app. Il indique aussi où rechercher les plugins et les bibliothèques.

build.gradle.kts à la racine : les plugins du projet

Dans notre projet de départ, il déclare les plugins et leurs versions. apply false signifie qu’on ne les applique pas à ce niveau ; ils seront utilisés dans le module concerné.

app/build.gradle.kts : comment construire l’app ?

On y retrouve les plugins appliqués à app, les réglages Android, l’activation de Compose et les dépendances utilisées par ce module.

Ces fichiers se terminent par .gradle.kts : ils décrivent le travail de Gradle avec une syntaxe Kotlin. Ils ne décrivent pas l’écran du quiz.

  1. Retrouve include(":app") dans les settings.
  2. Ouvre ensuite app/build.gradle.kts et repère minSdk, compose = true et dependencies.
  3. Explique pourquoi les deux fichiers nommés build.gradle.kts n’ont pas le même emplacement ni le même rôle.
Que signifient minSdk, compileSdk et targetSdk ?

minSdk fixe la version minimale d’Android acceptée. compileSdk choisit les API Android disponibles pour compiler. Une API est un ensemble de possibilités qu’un autre code peut utiliser, par exemple les fonctions fournies par Android. targetSdk indique la version d’Android pour laquelle l’app déclare avoir été adaptée, ce qui influence certains comportements du système. Ces nombres répondent à des besoins différents ; les repérer ne demande pas de les changer.

💡

Module

Une partie du projet qui possède sa configuration de construction. Ici, app est le module de l’application Android.

💡

Racine · root

Le dossier principal du clone. Le terminal de cet exercice doit être placé dans ce dossier, au même niveau que gradlew.

💡

SDK

Software Development Kit : un ensemble d’outils et de ressources pour développer sur une plateforme. L’IDE a déjà aidé à préparer le SDK Android.

03 / Utiliser du code fourni par d’autres

Une dépendance rend une bibliothèque disponible.

Tu utilises Text et Button sans avoir écrit leur fonctionnement. Ils viennent d’une bibliothèque, un ensemble de code réutilisable. Déclarer une dépendance indique à Gradle que ton module a besoin de cette bibliothèque.

Voici un extrait déjà présent dans le projet de départ, à lire dans le fichier plutôt qu’à ajouter une seconde fois :

dependencies {
    implementation("androidx.compose.material3:material3")
}

implementation déclare ici une bibliothèque utilisée par le module app. Le nom avant les deux-points situe sa famille ; celui après identifie la bibliothèque. Un import Kotlin permet ensuite d’utiliser ses noms dans un fichier de code : l’import et la déclaration Gradle ont donc des rôles complémentaires.

Pourquoi certaines lignes ont-elles une version et pas celle-ci ?

Le projet de départ utilise une BOM Compose, une liste de versions prévues pour fonctionner ensemble. Elle fournit les versions des bibliothèques Compose concernées. D’autres dépendances indiquent directement leur version. Dans d’autres projets, ces informations peuvent aussi être rangées dans un catalogue. Pour cette page, retrouve l’organisation de ton clone sans mettre les versions à jour.

Quand une bibliothèque manque sur l’ordinateur, Gradle peut la télécharger depuis un dépôt configuré, puis la garder dans son cache local. Le guide s’ouvre hors ligne ; construire Android peut demander une connexion, notamment lors de la première préparation.

Ajouter une bibliothèque ajoute-t-il automatiquement une fonctionnalité au quiz ?

Non. Cela rend du code disponible. Il reste à l’utiliser et à vérifier le résultat : déclarer une bibliothèque de caméra ne crée pas l’écran de capture.

💡

Dépendance · dependency

Un élément dont ton projet a besoin. Ici, une bibliothèque déclarée pour le module app.

💡

Dépôt de bibliothèques · repository

Un endroit où Gradle recherche des bibliothèques, par exemple Google Maven ou Maven Central. Le mot dépôt ne désigne pas ici ton historique Git.

💡

Cache

Une copie locale conservée pour éviter de refaire certains téléchargements ou travaux.

04 / Lancer la version choisie pour le projet

Utilise le Gradle Wrapper du clone.

Le Wrapper est le lanceur Gradle livré avec le projet. Les scripts gradlew et gradlew.bat, avec les fichiers de gradle/wrapper/, permettent d’utiliser la version de Gradle choisie pour ce projet. Elle est indiquée par distributionUrl dans gradle-wrapper.properties.

Tu n’as donc pas besoin d’installer une autre version de Gradle pour cet exercice. Le Wrapper télécharge celle du projet si elle n’est pas déjà disponible. Le JDK et le SDK Android doivent, eux aussi, être correctement préparés.

Une tâche, ou task, est un travail qu’on demande à Gradle. Dans :app:assembleDebug, :app désigne le module et assembleDebug la tâche qui assemble sa version de développement. Gradle organise aussi les tâches nécessaires avant celle-ci.

Windows · PowerShell

.\gradlew.bat :app:tasks --all

macOS / Linux · terminal

./gradlew :app:tasks --all

tasks liste les tâches ; --all élargit la liste. Lance seulement la commande qui correspond à ton terminal, depuis la racine du clone Android. Dans le résultat, cherche assembleDebug et installDebug.

J’utilise Git Bash sous Windows

Depuis la racine du clone, tu peux utiliser ./gradlew :app:tasks --all, puis ./gradlew :app:assembleDebug pour construire. Les exemples PowerShell utilisent explicitement le script Windows ; choisis la forme adaptée au terminal ouvert.

💡

Wrapper · lanceur du projet

Les fichiers qui permettent de lancer Gradle avec la version prévue par le projet.

💡

Task · tâche

Un travail nommé. Les plugins fournissent notamment les tâches de construction Android.

💡

JDK

Java Development Kit : les outils Java nécessaires notamment au fonctionnement de Gradle. Le terminal et l’IDE doivent utiliser une version compatible avec le projet.

05 / Ton résultat observable

Construis l’APK et retrouve le fichier.

  1. Enregistre les fichiers du quiz dans l’IDE. Vérifie que tu es dans le clone Android, avec gradlew et le dossier app visibles à la racine.
  2. Avant de lancer la commande, annonce ce qu’elle doit produire et si elle doit ouvrir l’appareil.
  3. Lance la commande correspondant à ton terminal, puis attends la fin du travail.

Windows · PowerShell

.\gradlew.bat :app:assembleDebug

macOS / Linux · terminal

./gradlew :app:assembleDebug

Dans la sortie, repère les lignes > Task et le message final. Une construction réussie se termine par BUILD SUCCESSFUL. Si elle échoue, retrouve le premier message utile avec l’encadrant avant de réessayer.

Après réussite, ouvre ce chemin depuis le dossier du projet, dans l’explorateur de fichiers ou l’affichage Project de l’IDE :

app/build/outputs/apk/debug/app-debug.apk

Ce chemin correspond à notre module app dans sa configuration simple. Si le projet a été adapté, le nom ou les sous-dossiers peuvent varier : retrouve le dossier app/build/outputs/apk/ avec l’encadrant.

Résultat attendu : une construction réussie et un APK retrouvé.

assembleDebug ne demande pas d’appareil connecté et ne lance pas le quiz. L’APK sert au développement ; sa création ne publie rien sur GitHub ou Google Play.

La tâche installDebug peut construire puis installer sur un appareil préparé ; l’installation et l’ouverture de l’écran restent deux actions différentes. Pour cette première expérience, produire et retrouver le fichier suffit.

La deuxième construction va plus vite ou affiche UP-TO-DATE

UP-TO-DATE signifie que Gradle juge le résultat d’une tâche déjà à jour. FROM-CACHE indique qu’il réutilise un résultat du cache. Il n’est pas obligé de refaire chaque étape. Une nouvelle construction peut réussir sans changer la date de l’APK si rien n’a changé.

Un APK est présent, mais la dernière commande a échoué

Le fichier peut venir d’une construction précédente. Sa présence ne prouve pas la réussite de la dernière commande. Lis son résultat avant d’associer ce fichier à ta version actuelle.

Le terminal indique une erreur de Java, de SDK ou de téléchargement

Commence par vérifier le dossier courant. Pour Java, compare avec l’encadrant le JDK du terminal et celui utilisé par Gradle dans Android Studio. Pour le SDK, vérifiez son installation et le chemin local. Pour un téléchargement, lisez le nom de l’élément manquant et vérifiez la connexion. Une erreur d’environnement n’appelle pas forcément un changement du code du quiz ou des versions Gradle.

Sur macOS/Linux, si le script indique « Permission denied », fais vérifier ses droits avec l’encadrant. Le nom de fichier seul ne garantit pas qu’il est exécutable.

💡

Debug / release

Deux types de construction : debug pour développer, release pour préparer une distribution. Ici, on utilise debug ; la publication et sa signature seront un autre sujet.

💡

Artefact · artifact

Un fichier produit par la construction. Dans cette expérience, l’APK est l’artefact que tu retrouves.

💡

SUCCESSFUL / FAILED

« Réussi » / « échoué ». Le message final t’aide à distinguer une construction terminée avec succès d’une tentative interrompue par une erreur.

Question : ajouter un import suffit-il toujours à utiliser une nouvelle bibliothèque ?

Non. L’import permet de désigner du code déjà disponible. Si la bibliothèque n’est pas une dépendance du module, il faut d’abord la déclarer correctement et synchroniser le projet.

Question : BUILD SUCCESSFUL prouve-t-il que le quiz compte bien les points ?

Non. Cela confirme la réussite des tâches demandées. Il reste à observer le comportement du quiz, comme dans les pages précédentes.
