Les fonctions : décrire une action.

Tu as préparé la question, les choix et la bonne réponse. Écris maintenant une action qui vérifie si un choix est correct.

Une action peut avoir besoin d’informations et produire un résultat. Elle peut aussi travailler sans paramètre ou sans résultat utile à récupérer.

01 / Une tâche qui porte un nom

Pourquoi écrire une fonction ?

Une fonction décrit une action que le programme pourra exécuter. Son nom explique ce qu’elle fait. Pour vérifier plusieurs réponses, nous voulons réutiliser la même action plutôt que réécrire sa règle à chaque endroit.

  1. Ce qu’elle reçoit

    Les informations nécessaires : ici, le choix et la réponse attendue.

  2. Ce qu’elle fait

    Le travail : ici, comparer les deux textes.

  3. Ce qu’elle produit

    Un résultat à récupérer : ici, vrai ou faux.

Nous appellerons cette action isCorrectAnswer : « est-ce la bonne réponse ? ». Son résultat sera donc un Boolean.

Écrire sa définition décrit le travail. Pour que ce travail soit fait, il faudra ensuite appeler la fonction.

💡

Fonction · function

Une action nommée que le programme peut exécuter. Elle peut recevoir des paramètres et renvoyer un résultat, mais ces deux éléments ne sont pas obligatoires.

💡

Paramètre · parameter

Une information que l’action doit connaître pour travailler. Dans sa définition, chaque paramètre a un nom et un type.

02 / La règle de notre action

Poser une question avec ==.

Tu connais = dans une déclaration : il donne une valeur à une variable. Pour demander si deux valeurs sont égales, Kotlin utilise deux signes : ==.

val selectedAnswer: String = "Git"
val correctAnswer: String = "Git"
val result: Boolean = selectedAnswer == correctAnswer

La dernière ligne se lit : « Le choix est-il égal à la bonne réponse ? Je conserve le résultat dans result. » Ici, le résultat vaut true.

Si le choix est "Android", le résultat vaut false. Pour ces textes, la comparaison tient compte des majuscules et des espaces : "git" et "Git" ne sont pas égaux.

À toi : que donne "Git" == "Git " ?

false : le deuxième texte contient un espace supplémentaire à la fin. Notre règle vérifie l’égalité exacte des textes.

💡

Comparer · compare

Poser une question sur des valeurs. Ici, == vérifie leur égalité et produit true ou false.

💡

selectedAnswer / correctAnswer

La réponse choisie / la bonne réponse. Les noms décrivent leur rôle, même si les deux contiennent parfois le même texte.

💡

result · résultat

Le nom donné ici au résultat de la comparaison.

03 / Décrire le travail

Écris la fonction de validation.

Notre action reçoit deux textes et renvoie un booléen :

fun isCorrectAnswer(
    selectedAnswer: String,
    correctAnswer: String,
): Boolean {
    val result: Boolean = selectedAnswer == correctAnswer
    return result
}
fun
Indique que nous déclarons une fonction.
isCorrectAnswer
Le nom de l’action. Un nom explicite aide à comprendre son rôle dans le reste du code.
(selectedAnswer: String, correctAnswer: String)
Les paramètres entre parenthèses, séparés par une virgule : les informations que l’action attend.
: Boolean
Le type du résultat que l’action fournit.
{ … }
Le corps de la fonction, avec ses instructions.
val result: Boolean = …
Une variable créée pour conserver le résultat du travail.
return result
Termine cet appel et transmet le résultat au code qui a appelé la fonction.

Les paramètres sont déjà les noms des informations reçues : on n’écrit pas val devant eux. Nous gardons result pour bien voir les étapes ; une écriture plus courte sera possible plus tard.

💡

Corps · body

Les instructions entre les accolades { et } de la fonction. C’est là que l’action décrit son travail.

💡

return · renvoyer

Termine l’appel en cours et donne une valeur au code appelant. Cela n’affiche pas le résultat à l’écran.

💡

Type de retour · return type

Le type du résultat que la fonction promet de renvoyer. Ici, Boolean.

04 / Faire exécuter l’action

Appeler avec des valeurs précises.

On utilise le nom de la fonction suivi de parenthèses contenant les valeurs à lui transmettre :

val firstChoice: String = "Git"
val secondChoice: String = "Android"
val correctAnswer: String = "Git"

val isFirstChoiceCorrect: Boolean = isCorrectAnswer(firstChoice, correctAnswer)
val isSecondChoiceCorrect: Boolean = isCorrectAnswer(secondChoice, correctAnswer)

Dans le premier appel, firstChoice fournit « Git » au paramètre selectedAnswer, et correctAnswer fournit « Git » au second paramètre. La fonction travaille, puis son résultat devient la valeur de isFirstChoiceCorrect.

Le deuxième appel fournit « Android » comme choix. C’est la même action, avec une information différente.

Prévoir les deux résultats, puis vérifier mon raisonnement

isFirstChoiceCorrect vaut true ; isSecondChoiceCorrect vaut false. Chaque appel fait son propre travail avec les valeurs reçues.

Définir et appeler sont deux étapes différentes.

La définition explique comment vérifier une réponse. L’appel demande cette vérification pour un choix précis. Récupérer le résultat dans une variable ne l’affiche pas automatiquement.

💡

Appeler · call

Demander l’exécution d’une fonction en écrivant son nom suivi de parenthèses.

💡

Argument · argument

Une valeur fournie lors d’un appel. Le paramètre est le nom attendu dans la définition ; l’argument est ce qu’on lui transmet dans un appel précis.

💡

isFirstChoiceCorrect

« Le premier choix est-il correct ? » : le nom décrit le résultat que l’on conserve.

05 / Où peut-on utiliser une variable ?

La portée dépend de son emplacement.

Une variable peut être déclarée à plusieurs endroits. Son emplacement détermine où le code peut utiliser son nom : c’est sa portée.

Au niveau du fichier

Voici un exemple séparé où la bonne réponse est déclarée en dehors des fonctions. Il sert à comparer les emplacements, pas à remplacer notre fonction à deux paramètres.

val correctAnswer: String = "Git"

fun checkAnswer(selectedAnswer: String): Boolean {
    val result: Boolean = selectedAnswer == correctAnswer
    return result
}

Dans ce fichier, les fonctions peuvent lire correctAnswer. Ce n’est pas parce qu’elles sont écrites en dessous : cette déclaration reste accessible dans le fichier même si une fonction est définie au-dessus. On parle ici de l’accès à son nom, pas de l’ordre dans lequel les actions sont exécutées.

Dans le corps d’une fonction

result est une variable locale : elle est déclarée à l’intérieur de checkAnswer. Le code qui suit dans ce corps, y compris ses éventuels blocs imbriqués, peut l’utiliser. Une autre fonction ne peut pas lire directement cette variable locale.

Le paramètre selectedAnswer est lui aussi accessible dans le corps de cet appel. Pour transmettre le résultat vers l’extérieur, on utilise return. L’appelant récupère la valeur, sans accéder directement au nom local result.

Pourquoi notre fonction finale reçoit-elle aussi correctAnswer ?

Une bonne réponse fixée dans le fichier fonctionnerait pour cet exemple. En la recevant comme paramètre, isCorrectAnswer peut vérifier d’autres questions : chaque appel lui fournit les deux informations nécessaires. Sa règle ne dépend plus de la réponse « Git » déclarée ailleurs.

💡

Portée · scope

La partie du code dans laquelle un nom est accessible. Elle dépend de l’endroit où on déclare ce nom.

💡

Au niveau du fichier · top-level

Une déclaration placée en dehors des fonctions et des classes. Ici, nous regardons son utilisation dans le même fichier.

💡

Locale · local

Une variable créée dans un bloc pour son travail. Les accolades aident à repérer ce bloc.

06 / Une action sans résultat à récupérer

Découvrir Unit avec un message d’aide.

Une action ne doit pas forcément fournir une réponse ou un nombre. Elle peut simplement afficher un message :

fun showHelp(): Unit {
    println("Choisis une réponse pour continuer.")
}

showHelp signifie « afficher l’aide ». Les parenthèses sont vides : cette action n’attend aucun paramètre. Son corps utilise println, une fonction Kotlin qui écrit un message dans la console, puis passe à la ligne.

: Unit indique qu’il n’y a pas de résultat utile à récupérer. L’action a un effet — écrire le message — sans fournir un booléen ou un texte de réponse. Kotlin permet de ne pas écrire : Unit ; nous le gardons ici pour rendre ce cas visible.

Pour demander l’action :

showHelp()

Écrire la définition ne suffit pas à afficher le message ; cet appel doit être exécuté. Ici, le message va dans une console, pas sur l’écran Android. Une action peut aussi recevoir des paramètres et avoir un retour Unit : les entrées et le résultat sont deux choix indépendants.

💡

Unit

Le type utilisé pour une action qui ne fournit pas de résultat utile à récupérer. On n’a pas besoin d’écrire return dans cet exemple.

💡

Console

Une zone de sortie de texte utilisée pour observer les messages d’un programme. Elle ne construit pas l’interface de l’application.

07 / Ta règle de validation

Utilise la même action pour les trois choix.

  1. Reprends les valeurs de ta question et écris la fonction isCorrectAnswer à deux paramètres.
  2. Écris trois appels, un pour chaque choix, en conservant leurs résultats dans des variables Boolean aux noms explicites.
  3. Avant de vérifier, annonce le résultat attendu pour chacun et explique les valeurs que l’action recevra.
  4. Montre les paramètres, le corps, la variable locale et le retour de la fonction à ton encadrant.
Où placer la fonction dans le projet Android ?

Avec l’encadrant, tu peux ajouter uniquement la définition de isCorrectAnswer à la fin de MainActivity.kt, après la dernière accolade et en dehors des autres fonctions et classes. Si elle existe déjà, ne la déclare pas une deuxième fois.

La fonction peut alors être compilée avec le projet, mais aucun bouton ne l’appelle encore. Garde les appels d’exercice pour la vérification ci-dessous ; leur branchement à l’écran arrivera dans la partie interface.

Avec l’encadrant : vérifier dans un petit programme console

L’exemple complet ci-dessous peut être exécuté dans un environnement Kotlin console préparé par l’encadrant. main est son point de départ, fourni pour exécuter les appels. Ce n’est pas le point de départ de l’application Android : ne colle pas ce programme complet dans MainActivity.kt.

fun isCorrectAnswer(
    selectedAnswer: String,
    correctAnswer: String,
): Boolean {
    val result: Boolean = selectedAnswer == correctAnswer
    return result
}

fun showHelp(): Unit {
    println("Choisis une réponse pour continuer.")
}

fun main(): Unit {
    val questionText: String = "Quel outil garde l’historique du code ?"
    val firstChoice: String = "Git"
    val secondChoice: String = "Android"
    val thirdChoice: String = "Compose"
    val correctAnswer: String = "Git"

    val isFirstChoiceCorrect: Boolean = isCorrectAnswer(firstChoice, correctAnswer)
    val isSecondChoiceCorrect: Boolean = isCorrectAnswer(secondChoice, correctAnswer)
    val isThirdChoiceCorrect: Boolean = isCorrectAnswer(thirdChoice, correctAnswer)

    println(questionText)
    showHelp()
    println(isFirstChoiceCorrect)
    println(isSecondChoiceCorrect)
    println(isThirdChoiceCorrect)
}

Résultat attendu : l’énoncé, le message d’aide, puis true, false, false sur trois lignes. Adapte les attentes si tu as écrit une autre question.

Question : puis-je lire result depuis une autre fonction ?

Pas directement : result est locale à notre fonction. Tu peux en revanche appeler la fonction et conserver la valeur qu’elle renvoie dans une autre variable.

Question : return et println font-ils la même chose ?

Non. return transmet un résultat au code appelant et termine l’appel. println écrit un message dans la console ; ce n’est pas un retour de validation.
