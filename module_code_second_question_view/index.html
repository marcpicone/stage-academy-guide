01 / Partir de ce qui marche

Garde un premier point de repère.

Dans ton projet Android, reprends la version de la page précédente. Vérifie que Git donne « Bonne réponse ! », et que les deux autres boutons donnent « Essaie encore. ».

Avec l’encadrant, garde cette étape dans Git avant de modifier l’écran. Pour la suite, tu peux préparer une branche comme ab/ajouter_deuxieme_question, en utilisant tes initiales et un point de départ qui contient ta première question fonctionnelle.

Le but n’est pas encore de faire défiler les questions une à une ou de calculer un score. Tu vas construire deux groupes de réponses indépendants dans le même écran.

💡

Point de départ

La version du projet sur laquelle tu travailles. Relancer et vérifier son comportement aide à distinguer un problème déjà présent d’un problème introduit ensuite.

02 / Distinguer les informations

Quelle valeur appartient à quelle question ?

Si tu recopies les cinq déclarations de la première question dans le même bloc sans changer leurs noms, le programme ne pourra pas distinguer les deux groupes. Donne des noms différents aux valeurs qui appartiennent aux deux questions.

Pour la première, fais apparaître firstQuestion dans les noms :

val firstQuestionText: String = "Quel outil garde l’historique du code ?"
val firstQuestionFirstChoice: String = "Git"
val firstQuestionSecondChoice: String = "Android"
val firstQuestionThirdChoice: String = "Compose"
val firstQuestionCorrectAnswer: String = "Git"

Prépare ensuite la seconde question sur Compose :

val secondQuestionText: String = "Quel composant Compose affiche du texte ?"
val secondQuestionFirstChoice: String = "Button"
val secondQuestionSecondChoice: String = "Text"
val secondQuestionThirdChoice: String = "Column"
val secondQuestionCorrectAnswer: String = "Text"

Quand tu renommes les valeurs de la première question, mets aussi à jour leurs utilisations dans les boutons, le texte et la validation. L’action de renommage de l’IDE peut t’aider avec l’encadrant ; relis les changements avant de continuer.

Des noms longs mais explicites évitent les confusions.

secondQuestionSecondChoice signifie « deuxième choix de la deuxième question ». Ce nom dit précisément ce que tu lis. Il montre aussi que les noms commencent à devenir encombrants.

💡

first / second

Premier / deuxième. Ici, ces mots distinguent les deux questions, puis leurs choix.

💡

Portée · scope

Dans le même bloc, deux variables locales ne peuvent pas porter le même nom. Nous gardons toutes les données au début de WelcomeScreen pour cet exercice.

💡

Renommer · rename

Changer un nom et ses utilisations pour conserver leur lien. Modifier seulement la déclaration laisse des utilisations avec l’ancien nom.

03 / Un message par question

Réutilise la règle, distingue les actions.

Garde une seule fonction isCorrectAnswer au niveau du fichier. Sa règle compare deux textes, quelle que soit la question. Elle n’a pas besoin d’être recopiée.

En revanche, chaque question doit garder son propre message :

var firstFeedbackText: String by remember {
    mutableStateOf("Choisis une réponse pour la question 1.")
}
var secondFeedbackText: String by remember {
    mutableStateOf("Choisis une réponse pour la question 2.")
}

L’action de la première question devient checkFirstAnswer et utilise firstQuestionCorrectAnswer puis firstFeedbackText. Écris celle de la deuxième sur le même modèle :

fun checkSecondAnswer(selectedAnswer: String): Unit {
    val isAnswerCorrect: Boolean = isCorrectAnswer(
        selectedAnswer,
        secondQuestionCorrectAnswer,
    )
    if (isAnswerCorrect) {
        secondFeedbackText = "Bonne réponse !"
    } else {
        secondFeedbackText = "Essaie encore."
    }
}

Vérifie les deux liens : la bonne réponse vient de la deuxième question, et le message modifié est celui de la deuxième question. Les deux actions restent à l’intérieur de WelcomeScreen pour accéder aux données qui les entourent.

Pourquoi les deux actions peuvent-elles avoir une variable isAnswerCorrect ?

Chacune déclare cette variable dans son propre corps. Les deux variables sont locales à deux fonctions différentes. Elles ne se gênent pas. Ce n’est pas la même situation que deux déclarations du même nom dans le même bloc.

💡

Indépendant · independent

Répondre à la deuxième question doit changer son message, sans remplacer celui de la première.

💡

Réutiliser · reuse

Appeler la même règle avec d’autres valeurs. isCorrectAnswer reçoit deux textes : cette action sert aux deux questions.

04 / Compléter la vue

Ajoute le deuxième groupe de boutons.

Dans Column, garde l’ordre suivant : titre, question 1, ses trois boutons, son message, puis question 2, ses trois boutons et son message.

Par exemple, le bouton du deuxième choix de la deuxième question utilise cette même valeur à deux endroits :

Button(onClick = { checkSecondAnswer(secondQuestionSecondChoice) }) {
    Text(text = secondQuestionSecondChoice)
}

Le bouton affiche « Text » et transmet « Text » à l’action de la deuxième question. Relis chaque bouton pour éviter qu’il affiche un choix mais en vérifie un autre.

Deux questions peuvent dépasser la hauteur de l’appareil. Le cadre fourni ajoute verticalScroll(rememberScrollState()) à Column pour permettre le défilement vertical. Ajoute ces deux imports s’ils ne sont pas déjà présents :

import androidx.compose.foundation.rememberScrollState
import androidx.compose.foundation.verticalScroll
Comparer avec une version complète de WelcomeScreen

Essaie d’abord de compléter tes données et tes boutons. Utilise ce bloc pour comparer ou reprendre un point précis avec l’encadrant. Si tu le remplaces entièrement, garde le reste du fichier et l’unique fonction isCorrectAnswer.

@Composable
fun WelcomeScreen(modifier: Modifier = Modifier) {
    val firstQuestionText: String = "Quel outil garde l’historique du code ?"
    val firstQuestionFirstChoice: String = "Git"
    val firstQuestionSecondChoice: String = "Android"
    val firstQuestionThirdChoice: String = "Compose"
    val firstQuestionCorrectAnswer: String = "Git"

    val secondQuestionText: String = "Quel composant Compose affiche du texte ?"
    val secondQuestionFirstChoice: String = "Button"
    val secondQuestionSecondChoice: String = "Text"
    val secondQuestionThirdChoice: String = "Column"
    val secondQuestionCorrectAnswer: String = "Text"

    var firstFeedbackText: String by remember {
        mutableStateOf("Choisis une réponse pour la question 1.")
    }
    var secondFeedbackText: String by remember {
        mutableStateOf("Choisis une réponse pour la question 2.")
    }

    fun checkFirstAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = isCorrectAnswer(
            selectedAnswer,
            firstQuestionCorrectAnswer,
        )
        if (isAnswerCorrect) {
            firstFeedbackText = "Bonne réponse !"
        } else {
            firstFeedbackText = "Essaie encore."
        }
    }

    fun checkSecondAnswer(selectedAnswer: String): Unit {
        val isAnswerCorrect: Boolean = isCorrectAnswer(
            selectedAnswer,
            secondQuestionCorrectAnswer,
        )
        if (isAnswerCorrect) {
            secondFeedbackText = "Bonne réponse !"
        } else {
            secondFeedbackText = "Essaie encore."
        }
    }

    Column(
        modifier = modifier
            .fillMaxSize()
            .verticalScroll(rememberScrollState())
            .padding(24.dp),
        verticalArrangement = Arrangement.spacedBy(16.dp),
        horizontalAlignment = Alignment.CenterHorizontally,
    ) {
        Text(
            text = stringResource(R.string.welcome_title),
            style = MaterialTheme.typography.headlineMedium,
        )
        Text(text = "Question 1", style = MaterialTheme.typography.titleMedium)
        Text(text = firstQuestionText)
        Button(onClick = { checkFirstAnswer(firstQuestionFirstChoice) }) {
            Text(text = firstQuestionFirstChoice)
        }
        Button(onClick = { checkFirstAnswer(firstQuestionSecondChoice) }) {
            Text(text = firstQuestionSecondChoice)
        }
        Button(onClick = { checkFirstAnswer(firstQuestionThirdChoice) }) {
            Text(text = firstQuestionThirdChoice)
        }
        Text(text = firstFeedbackText)
        Text(text = "Question 2", style = MaterialTheme.typography.titleMedium)
        Text(text = secondQuestionText)
        Button(onClick = { checkSecondAnswer(secondQuestionFirstChoice) }) {
            Text(text = secondQuestionFirstChoice)
        }
        Button(onClick = { checkSecondAnswer(secondQuestionSecondChoice) }) {
            Text(text = secondQuestionSecondChoice)
        }
        Button(onClick = { checkSecondAnswer(secondQuestionThirdChoice) }) {
            Text(text = secondQuestionThirdChoice)
        }
        Text(text = secondFeedbackText)
    }
}

La deuxième question n’apparaît pas seulement après la première : les deux sont dans cet écran. Fais défiler pour atteindre le bas et tous les boutons.

💡

Défilement · scroll

Déplacer le contenu à l’écran pour voir ce qui dépasse. Le code de défilement est fourni ici pour rendre les deux questions accessibles.

💡

Correspondance

Le texte affiché, l’argument transmis au clic et le message mis à jour doivent appartenir au même groupe de question.

05 / Vérifier les liens

Deux questions, deux résultats indépendants.

Enregistre puis lance avec Run. Prévois chaque résultat avant de cliquer.

  1. Question 1 : clique sur Git. Son message doit devenir « Bonne réponse ! ».
  2. Descends vers la question 2 : son message doit encore proposer de choisir une réponse.
  3. Question 2 : clique sur Button, puis Text. Son message doit passer de « Essaie encore. » à « Bonne réponse ! ».
  4. Remonte : le message de la question 1 doit toujours indiquer « Bonne réponse ! ».
  5. Question 1 : clique sur Android. Seul son message devient « Essaie encore. ».
  6. Question 2 : clique sur Column. Son message devient « Essaie encore. ».
Une réponse modifie le mauvais message

Pars du bouton : quelle action appelle son onClick ? Quelle valeur est transmise ? Dans cette action, quelle bonne réponse est utilisée et quel message est changé ? Compare les préfixes first et second. Un nom existant mais appartenant à l’autre question peut compiler tout en donnant un comportement incorrect.

La deuxième question ne tient pas à l’écran

Vérifie les deux imports et le modifier verticalScroll dans le bloc complet. Essaie de faire défiler sur l’appareil, pas seulement de regarder le premier écran visible.

💡

Test de comportement

Vérifier ce que l’application fait vraiment. Une compilation réussie ne détecte pas tous les mélanges entre les deux questions.

06 / Observer avant d’organiser

Et si tu ajoutais encore deux questions ?

Ne les code pas encore : cherche ce qu’il faudrait recopier ou renommer. Montre les données, les actions et les boutons concernés à ton encadrant.

  1. Quelles informations reviennent pour chaque question ?
  2. Quelles lignes ont la même forme, avec seulement un nom ou un texte différent ?
  3. Où risquerais-tu de garder par erreur une référence à la première question ?
  4. Qu’est-ce qui est déjà partagé sans être recopié ?
Comparer mes observations

Chaque question possède un énoncé, des choix, une bonne réponse et un message. Les deux actions de clic et les groupes de boutons se ressemblent beaucoup. La validation isCorrectAnswer est déjà commune.

Le code fonctionne, mais ajouter des questions oblige à suivre de plus en plus de noms et de liens. Nous allons maintenant chercher à regrouper les informations et à réutiliser davantage de code.
